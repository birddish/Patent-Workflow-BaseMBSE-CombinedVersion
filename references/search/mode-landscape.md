
# 专利态势分析模式指南

> **适用场景**：针对特定技术领域，分析专利布局趋势、主要申请人、技术分类分布和年度变化，形成专利地图（Patent Landscape）。
> **共用基础**：本文件仅含本模式特有内容。通用流程、模板及验证门详见 [stage-templates.md](stage-templates.md) 和 [search-guide.md](search-guide.md)。

---

## 一、模式速查

| 维度                   | 本模式设定                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------- |
| **调查对象**     | 技术领域的文献集定义（技术范围+时间段+地域）                                           |
| **分解对象**     | 不进行技术特征分解；改为**文献集定义**（技术边界、IPC/CPC 范围、时间窗口、地域） |
| **权利状态限定** | 无——所有公开文献均可纳入统计分析                                                     |
| **筛选视角**     | 按分类、申请人、年度进行数据整理和分布分析                                             |
| **评价形式**     | 专利地图（Patent Map）：件数推移图、申请人排名、分类分布、技术成熟度曲线等             |
| **最终产出**     | 专利地图可视化 + 趋势解读 + 主要申请人/技术方向分析                                    |

---

## 二、适用验证门

| 验证门      | 适用？     | 说明                                                                                         |
| ----------- | ---------- | -------------------------------------------------------------------------------------------- |
| ① 实存     | ✅         | 统计数据所依据的文献须经书目核验                                                             |
| ② 覆盖性   | ✅（变体） | 覆盖性门在本模式中变为**代表性验证**——检索式是否合理覆盖了目标技术领域的代表性文献集 |
| ③ 对比     | ❌ 不适用  | 不进行逐件文献的技术特征对比                                                                 |
| ④ 法律状态 | ❌ 不适用  | 不关心专利的有效性，仅统计公开趋势                                                           |
| ⑤ 强度     | ✅（宽松） | 避免从统计趋势中过度推断因果关系                                                             |

## 三、各阶段模式差异

### 工程1 — 检索方案设计

#### 3.1.1 文献集定义（替代技术特征分解）

| 维度               | 定义                                | 示例                              |
| ------------------ | ----------------------------------- | --------------------------------- |
| **技术范围** | 目标技术的 IPC/CPC 分类和关键词范围 | B60L 50/00（电动车辆）相关        |
| **时间窗口** | 分析的时间范围                      | 2015-2025（近10年）               |
| **地域范围** | 统计覆盖的国家/地区                 | CN/US/JP/KR/EP/WO 六法域          |
| **排除条件** | 需要排除的文献类型（如有）          | 排除外观设计，仅统计发明+实用新型 |

#### 3.1.2 分析维度定义

明确需要制作哪些维度的分析：

- [ ] 年度申请/公开件数推移
- [ ] 主要申请人/专利权人排名
- [ ] IPC/CPC 分类分布
- [ ] 技术成熟度/生命周期分析
- [ ] 国家/地区分布
- [ ] 申请人类型分布（企业/大学/个人）
- [ ] 引用关系/核心专利识别

### 工程2 — 检索策略

- **检索式设计目标**：兼顾召回率（不漏重要文献）和精确率（减少噪声对统计的干扰）。
- **benchmark 的作用**：用于验证检索是否覆盖了已知的代表性文献，而非验证新颖性/无效证据的命中。
- 与通用流程一致。

### 工程3 — 正式检索与筛选

- **筛选方式**：与通用流程有本质区别：
  - 不逐件精读文献
  - 基于书目信息（分类号、申请人、日期）进行批量分类统计
  - 噪声文献（不相关领域）在统计前排除（记录排除标准与数量）
- **数据清洗**：注意同一申请人的名称变体（子公司、译名差异），进行归一化处理。

### 工程4 — 对比分析（在本模式中变为专利地图制作）

> ⚠️ 本模式不制作技术特征对比表，不进行 X/Y/A 等级评定。

#### 4.1 年次推移图

```
年度申请件数
  |
  |     ┌─ 快速增长期
  |   ┌─┘
  | ┌─┘  ┌── 平台期
  |─┘  ┌─┘
  +───────────────── 年度
```

#### 4.2 申请人排名

| 排名 | 申请人     | 申请件数 | 占比 | 主要技术方向 |
| ---- | ---------- | -------- | ---- | ------------ |
| 1    | XX公司     | 1,234    | 15%  | B60L, H02J   |
| 2    | YY株式会社 | 987      | 12%  | H01M         |

#### 4.3 分类分布

| IPC/CPC    | 件数  | 占比 | 趋势    |
| ---------- | ----- | ---- | ------- |
| B60L 50/00 | 5,000 | 40%  | ↑ 增长 |
| H02J 7/00  | 3,200 | 25%  | → 平稳 |

#### 4.4 技术成熟度曲线（可选）

按申请件数增长率 + 申请人数量变化判断技术生命周期阶段：萌芽期 → 成长期 → 成熟期 → 衰退期。

### 工程5 — 报告书

- **结论限定表述示例**：
  - ✅ "2018–2022年间，固态电池相关专利申请年均增长 35%，呈现快速增长态势"
  - ✅ "XX公司以 1,234 件申请位居榜首，主要布局在电解质材料方向"
  - ❌ "XX公司是该领域的绝对领导者"（主观评价，禁止）

## 四、模式专属审查要点

| #  | 检查项                                                   | 严重度   |
| -- | -------------------------------------------------------- | -------- |
| L1 | 文献集定义是否明确（技术边界、时间窗口、IPC/CPC 范围）？ | CRITICAL |
| L2 | 检索式的代表性是否经过 benchmark 验证？                  | HIGH     |
| L3 | 是否将对比门或法律状态门错误地应用于本模式？             | MEDIUM   |
| L4 | 统计结论是否有数据支撑（件数、比例、趋势）而非主观判断？ | HIGH     |
| L5 | 数据清洗是否记录了归一化规则（申请人名称统一等）？       | MEDIUM   |
| L6 | 是否注意到近18个月未公开申请的统计盲区？                 | MEDIUM   |
| L7 | 图表是否标注了数据来源、检索日期和文献集规模？           | LOW      |

## 六、交付物清单

> `quick/standard` 使用 [delivery-profiles.md](delivery-profiles.md) 的最小交付；统计工作簿、专利地图与正式报告仅在 `formal` 必需。

> 阶段2–4可先以最小 Markdown 运行记录保存检索式、数据库、命中数、日期、结果文件及异常状态；本节列示的 Excel 策略与日志在工程5报告定稿前统一完成。

> 格式规则：统计数据优先用 **Excel (.xlsx)**（如图表源数据、排名表、分类分布）；分析解读和专利地图说明用 **Markdown**。

|  #  | 交付物                             | 必/可选 | 格式                             | 说明                                                                                                                   |
| :-: | ---------------------------------- | :-----: | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| D1 | **分析报告** (`report.md`) |  ✅ 必  | MD                               | 含10项标准内容（对比分析节替换为专利地图解读）；结论避免过度推断                                                       |
| D2 | **年次推移图**               |  ✅ 必  | 图表（PNG/SVG）+ 数据表（Excel） | 标注数据来源、检索日期、文献集规模                                                                                     |
| D3 | **申请人排名表**             |  ✅ 必  | Excel (.xlsx)                    | 含归一化处理说明（名称统一规则记录于 D7）                                                                              |
| D4 | **IPC/CPC 分类分布表**       |  ✅ 必  | Excel (.xlsx)                    | 含各级分类的件数、占比和趋势方向（↑→↓）                                                                             |
| D5 | **检索策略与日志**           |  ✅ 必  | Excel (.xlsx)                    | Sheet 1「检索策略」：文献集定义、检索块设计、分类选择理由；Sheet 2「检索日志」：每次执行的检索式全文、DB、命中数、日期 |
| D6 | **文献集定义记录**           |  ✅ 必  | MD                               | 技术边界、IPC/CPC 范围、时间窗口、地域范围、排除条件                                                                   |
| D7 | **数据清洗记录**             |  ✅ 必  | MD                               | 去重规则、申请人归一化规则、噪声排除标准与排除数量                                                                     |
| D8 | **统计盲区说明**             |  ✅ 必  | MD                               | 近18个月未公开申请的统计偏差说明及对趋势解读的影响评估                                                                 |
| D9 | 技术成熟度曲线                     | ⚪ 可选 | 图表 + 数据表（Excel）           | 萌芽→成长→成熟→衰退四阶段判断依据                                                                                   |
| D10 | 引用关系/核心专利识别              | ⚪ 可选 | Excel                            | 高被引专利列表 + 引用网络图（可选）                                                                                    |

## 七、常见错误

1. ❌ **文献集定义不清，检索范围随意调整** → 导致统计结果不可复现
2. ❌ **将专利态势分析当成查新检索来做** → 逐件精读文献、制作 Claim Chart 是不必要的
3. ❌ **未进行申请人名称归一化** → "华为技术有限公司"/"Huawei Technologies"可能被计为两个申请人
4. ❌ **忽略近18个月的统计偏差** → 未公开申请的缺失导致近期数据偏低，应在报告中说明
5. ❌ **从相关性推断因果性** → "A公司申请最多"不等于"A公司技术最强"
6. ❌ **未保留检索日志** → 趋势结论无法复现和验证

## 八、补充检索

> 当文献集代表性不足或发现新线索需扩展检索时，按 [search-guide.md §9 补充检索指导](search-guide.md) 执行。专利态势分析的典型触发场景：文献集代表性不足需扩大 IPC 范围、发现新的重要申请人名称变体需回溯检索。
