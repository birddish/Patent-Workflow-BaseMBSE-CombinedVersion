# 无效检索模式指南

> **适用场景**：针对已授权专利的权利要求，检索基准日前的公知文献，以评估该专利被无效的可能性。
> **共用基础**：本文件仅含本模式特有内容。通用流程、模板及验证门详见 [stage-templates.md](stage-templates.md) 和 [search-guide.md](search-guide.md)。

---

## 一、模式速查

| 维度 | 本模式设定 |
|------|-----------|
| **调查对象** | 目标专利的特定权利要求（需明确权利要求编号） |
| **分解对象** | 目标权利要求的全部技术特征（按全部技术特征原则拆分） |
| **权利状态限定** | 无——基准日前所有公知文献均可使用 |
| **基准日** | 目标专利的申请日/优先权日（以用户确认为准） |
| **筛选视角** | 寻找能使权利要求无效的公开内容 |
| **评价形式** | 核心文献 → 无效权利要求对照表（Invalidity Claim Chart） + X/Y/A 等级 |
| **最终产出** | 无效可能性初步评估 + 核心证据文献清单 + Claim Chart |

---

## 二、适用验证门

> 推进规则：下表的覆盖性要求适用于正式报告的完整覆盖表述。首次运行只需完成一次语法、范围和基准日检查并保存原始结果；benchmark 未命中登记为补检/限制，不阻断核心文献核验。

| 验证门 | 适用？ | 说明 |
|--------|--------|------|
| ① 实存 | ✅ | 所有证据文献须经书目核验 |
| ② 覆盖性 | ✅ | 六语全球统一式覆盖 CN/US/JP/KR/EP/WO/PCT，已知 benchmark 必须被命中 |
| ③ 对比 | ✅ | 核心文献须通过 MCP/可信全文定位到具体权利要求/段落/附图 |
| ④ 法律状态 | ✅ **关键** | 每件作为实质证据的文献必须确认其**公开日早于基准日**（不要求核验专利有效性） |
| ⑤ 强度 | ✅ | 避免断定"该专利可被无效"，改用"文献X单独/文献Y+Z组合可能使权利要求N无效" |

## 三、各阶段模式差异

### 工程1 — 检索方案设计

- **分解对象**：目标专利的独立权利要求（及关键从属权利要求）。按全部技术特征原则（All Elements Rule）将权利要求拆分为最小技术特征单元。
- **基准日**：必须明确是申请日还是优先权日，并在全流程中保持一致。如果优先权存在争议，应记录并分别讨论。
- **权利要求的选取**：优先分析独立权利要求；从属权利要求的附加特征单独标记。

#### 权利要求分解示例

```
目标专利: CNXXXXXXXXXB, 权利要求1
基准日: 2020-03-15（申请日）

| 记号 | 技术特征 |
|------|---------|
| A    | 一种XXX装置，包括： |
| B    | 第一部件，其配置为... |
| C    | 第二部件，与第一部件连接... |
| D    | 控制单元，用于根据... |
```

### 工程2 — 检索策略

- 与通用流程一致。benchmark 优先选取同一技术领域的已知文献和被审查过程中引用的对比文件。

### 工程3 — 正式检索与筛选

- **筛选视角**：寻找公开了权利要求全部或部分特征的文献。尤其关注：（a）单独公开全部特征的文献（X类），（b）公开主要特征+次要特征属于公知常识的文献（Y类）。
- **公知常识文献**：教科書、工具书、行业标准等可作为公知常识的佐证。

### 工程4 — 对比分析（核心差异）

#### 4.1 无效 Claim Chart

必须逐项对照权利要求的每个技术特征：

| 权利要求特征 | 文献D1公开位置 | 4值判定 | 如不充足，补充文献D2 |
|-------------|-------------|---------|-------------------|
| A（前序部分） | D1: ¶[0015] | 充足 | — |
| B（特征部分） | D1: ¶[0023], 图3 | 充足 | — |
| C | D1: ¶[0030] | 部分充足 | D2: ¶[0008] 补足剩余部分 |

#### 4.2 X/Y/A 等级评定

> 本节只适用于 `delivery_profile=formal`。`quick/standard` 只输出候选、核心候选、背景线索或待核验，不填写 X/Y/A、NB 或 IS。

| 等级 | 定义 | 无效含义 |
|------|------|---------|
| **X** | 单独可否定新颖性或创造性 | 该文献单独公开了权利要求的全部特征 → 可用于新颖性无效 |
| **Y** | 可与其他文献组合否定创造性 | 该文献公开了主要特征，差异部分由另一文献或公知常识补足 |
| **A** | 技术背景 | 不直接威胁有效性，仅说明技术现状 |

> ⚠️ 只有完成 MCP 全文核验并定位到具体实施例/段落的文献，才能用于实质无效结论。

### 工程5 — 报告书

- **结论限定表述示例**：
  - ✅ "文献 D1（XX专利）公开了权利要求1的全部技术特征，可能影响其新颖性"
  - ✅ "文献 D2 + D3 的组合可能使权利要求1不具备创造性"
  - ❌ "权利要求1可被无效""该专利无效"（断定表述，禁止）

## 四、模式专属审查要点

| # | 检查项 | 严重度 |
|---|--------|--------|
| I1 | 权利要求的全部技术特征是否被正确分解（无遗漏、无多余）？ | CRITICAL |
| I2 | 每件用作实质证据的文献是否已确认公开日 < 基准日？ | CRITICAL |
| I3 | Claim Chart 中的每个"充足"判定是否可定位到具体段落/附图？ | CRITICAL |
| I4 | X/Y 等级是否基于 MCP 全文核验？号级/摘要级文献是否被错误升格？ | CRITICAL |
| I5 | 是否区分了"影响新颖性"与"影响创造性"的不同证据要求？ | HIGH |
| I6 | 是否考虑了从属权利要求的附加特征（仅无效独立权利要求不代表全部无效）？ | HIGH |
| I7 | 公知常识的引用是否有佐证文献？ | MEDIUM |

## 六、交付物清单

> `quick/standard` 使用 [delivery-profiles.md](delivery-profiles.md) 的最小交付，X/Y/A 表和完整工作簿仅在 `formal` 必需。

> 阶段2–4可先以最小 Markdown 运行记录保存检索式、数据库、命中数、日期、结果文件及异常状态；本节列示的 Excel 策略与日志在工程5报告定稿前统一完成。

> 格式规则：适合表格处理的数据优先用 **Excel (.xlsx)**；含大量文本引用和 Claim Chart 对比的用 **Markdown**。

| # | 交付物 | 必/可选 | 格式 | 说明 |
|:--:|--------|:--:|------|------|
| D1 | **检索报告** (`report.md`) | ✅ 必 | MD | 含10项标准内容；结论用"可能使权利要求N无效"等限定表述 |
| D2 | **无效 Claim Chart** | ✅ 必 | MD 表格 | 逐权利要求特征标注：文献证据、公开位置（段落/图号）、4 值判定、组合补足说明 |
| D3 | **X/Y/A 等级评定表** | ✅ 必 | MD 表格 | X 级须单件文献覆盖全部特征；Y 级须注明组合文献及各自补足的特征 |
| D4 | **检索策略与日志** | ✅ 必 | Excel (.xlsx) | Sheet 1「检索策略」：检索块设计、分类逆引き、全球统一式、benchmark 验证；Sheet 2「检索日志」：每次执行的检索式全文、DB、命中数、日期、执行者、结果文件 |
| D5 | **号码清单** | ✅ 必 | Excel (.xlsx) | 含公开号、题目、证据等级、核验 DB 与日期、**公开日**字段（用于基准日前判断） |
| D6 | **公开日核验记录** | ✅ 必 | Excel (.xlsx) | 每件实质证据文献：公开号 + 公开日 + 核验渠道 + 是否早于基准日 |
| D7 | **从属权利要求分析** | ✅ 必（如存在从属权利要求） | MD | 独立权利要求被覆盖后，从属权利要求附加特征的单独覆盖分析 |
| D8 | **六法域覆盖核验表** | ✅ 必 | MD 表格 | CN/US/JP/KR/EP/WO 逐一标注覆盖状态 |
| D9 | 公知常识佐证文献 | ⚪ 可选 | 号码列表 | 组合无效中引用公知常识时提供佐证文献号 |

## 七、常见错误

1. ❌ **未确认证据文献的公开日是否早于基准日** → 公开日晚于基准日的文献不构成现有技术
2. ❌ **Claim Chart 中仅写"参见D1全文"而不指明具体段落/图号** → 必须定位到最小公开单元
3. ❌ **仅分析独立权利要求，忽略从属权利要求** → 即使独立权利要求被无效，从属权利要求可能仍然有效
4. ❌ **混淆申请日与优先权日** → 基准日选择直接影响可用证据范围
5. ❌ **将多件文献的零散片段拼凑为一个"X"等级** → X等级要求**单件**文献公开全部特征

## 八、补充检索

> 当回退至工程2或因新证据需扩展检索时，按 [search-guide.md §9 补充检索指导](search-guide.md) 执行。无效检索的典型触发场景：Claim Chart 中某特征仅有"部分充足"需补强证据、发现新的公知常识线索需举证。
