# FTO（自由实施调查）模式指南

> **适用场景**：在产品上市或进入特定市场前，调查指定权利判断地域内可能构成侵权风险的存续中专利权与审查中专利申请。
> **共用基础**：本文件仅含本模式特有内容。通用流程、模板及验证门详见 [stage-templates.md](stage-templates.md) 和 [search-guide.md](search-guide.md)。

---

## 一、模式速查

| 维度 | 本模式设定 |
|------|-----------|
| **调查对象** | 本公司产品/技术的具体规格/实施方案 |
| **分解对象** | 产品/技术的规格特征（按结构/功能/方法拆分） |
| **权利状态限定** | ⚠️ **仅限存续中的授权专利 + 审查中的专利申请**（失效、撤回、驳回、届满专利排除在外） |
| **权利判断地域** | 用户指定的需要作出权利风险判断的国家/地区（如：仅中国） |
| **六法域覆盖** | CN/US/JP/KR/EP/WO 六法域**文献覆盖**不等于**权利判断地域**；非指定地域文献仅用于现有技术、同族和风险线索 |
| **筛选视角** | 寻找权利要求可能覆盖（read on）本公司产品规格的专利/申请 |
| **评价形式** | 核心风险文献 → 按全部技术特征原则（All Elements Rule）制作 Claim Chart |
| **最终产出** | 风险专利清单 + 风险等级评估 + Claim Chart（不构成法律意见） |

---

## 二、适用验证门

| 验证门 | 适用？ | 说明 |
|--------|--------|------|
| ① 实存 | ✅ | 所有风险专利须经书目核验 |
| ② 覆盖性 | ✅ | 六语全球统一式覆盖六法域文献检索；但权利判断地域可与文献覆盖范围不同 |
| ③ 对比 | ✅ | 核心风险文献须通过 MCP/可信全文定位到具体权利要求/段落/附图 |
| ④ 法律状态 | ✅ **关键** | 每件作为实质风险结论的专利必须核验：是否有效/审查中/失效/届满，以及当前有效的权利要求文本 |
| ⑤ 强度 | ✅ | 避免断定"不侵权""无风险"，改用"在本次检索范围内，未发现权利要求完全覆盖本公司产品的存续专利" |

## 三、各阶段模式差异

### 工程1 — 检索方案设计（关键差异最多）

#### 3.1.1 权利判断地域 vs 六法域覆盖

```
FTO 权利判断地域：用户指定（例如：仅中国大陆）
六法域文献覆盖：CN/US/JP/KR/EP/WO 全部必查
→ 其他五法域文献用于：现有技术参考、同族追踪、风险线索
→ 不根据其他法域文献直接作出指定地域的侵权结论
```

#### 3.1.2 产品规格分解

以产品实际实施的规格/方案为基准，而非专利权利要求：

| 记号 | 产品规格特征 | 备注 |
|------|------------|------|
| P1 | 产品包含A组件... | |
| P2 | B组件的材料为... | |
| P3 | 控制方法采用X算法... | |

#### 3.1.3 权利状态限定

- ✅ **纳入**：授权且维持有效的专利、审查中的发明专利申请
- ❌ **排除**：失效专利、撤回申请、驳回申请、期限届满专利、未缴年费失效专利
- ⚠️ **注意**：实用新型和外观设计按用户确认的权利判断地域法规单独处理

### 工程2 — 检索策略

- 检索策略与通用流程一致。无模式特殊分类要求（FTO 更依赖关键词匹配而非分类）。

### 工程3 — 正式检索与筛选

- **筛选视角**：寻找可能覆盖（read on）本公司产品规格的权利要求。注意：
  - 权利要求的文字范围可能比具体实施例更宽
  - 等同原则（Doctrine of Equivalents）——根据权利判断地域法规决定是否考虑
- **法律状态初筛**：在筛选阶段即可排除明显失效/届满的专利，但需记录排除理由和核验渠道。

### 工程4 — 对比分析（核心差异）

#### 4.1 按全部技术特征原则制作 Claim Chart

```
产品规格特征 vs 专利权利要求

| 产品特征 | 专利X 权利要求1对应要素 | 是否覆盖？ | 依据 |
|---------|----------------------|-----------|------|
| P1（A组件） | "一种装置，包括第一模块..." | 是/否/不确定 | ¶[0012], 图2 |
| P2（B材料） | "其中...材料为..." | 否（产品用C材料）| 明确差异 |
```

#### 4.2 风险等级（替代 X/Y/A）

| 风险等级 | 定义 |
|---------|------|
| 🔴 **高风险** | 权利要求的所有要素在产品中均有对应，建议立即由专利律师评估 |
| 🟡 **中风险** | 大部分要素对应，差异部分可能落入等同范围，需要进一步法律分析 |
| 🟢 **低风险** | 存在明确差异，或专利即将届满/法律状态存疑 |
| ⚪ **排除** | 法律状态已确认失效/届满/未缴年费 |

> ⚠️ FTO 模式不使用 X/Y/A 等级（那是针对专利性的评价体系）。

### 工程5 — 报告书

- **结论限定表述示例**：
  - ✅ "专利 CNXXXXXXXXXB 的权利要求1覆盖了本公司产品的X特征，建议进行法律评估"
  - ✅ "本次检索未发现当前有效的中国专利权利要求完全覆盖本公司产品规格"
  - ❌ "本公司产品不侵犯任何专利权""无侵权风险"（断定表述，禁止）

## 四、模式专属审查要点

| # | 检查项 | 严重度 |
|---|--------|--------|
| F1 | 是否明确区分了"六法域文献覆盖范围"与"FTO 权利判断地域"？ | CRITICAL |
| F2 | 每件列为风险专利的文献是否已核验法律状态（有效/审查中/失效/届满）？ | CRITICAL |
| F3 | 是否错误地将失效/届满专利列为风险专利？ | CRITICAL |
| F4 | Claim Chart 是否严格按全部技术特征原则逐项对比？ | CRITICAL |
| F5 | 是否考虑了审查中申请的可能授权范围（而非仅当前权利要求）？ | HIGH |
| F6 | 其他五法域文献的用途是否已限制为"线索/参考"而非直接侵权结论？ | HIGH |
| F7 | 外观设计是否按用户要求纳入/排除？ | MEDIUM |
| F8 | 是否误将 X/Y/A 等级用于 FTO 评估？ | MEDIUM |

## 六、交付物清单

> `quick` 只输出风险线索和 `risk_register`，不得作侵权或 FTO 结论；`standard` 可核验风险候选的法律状态与权利要求证据，但不得形成可交接 FTO 结论；完整 Claim Chart 与正式报告仅在 `formal` 必需。

> 阶段2–4可先以最小 Markdown 运行记录保存检索式、数据库、命中数、日期、结果文件及异常状态；本节列示的 Excel 策略与日志在工程5报告定稿前统一完成。风险专利的法律状态与有效权利要求核验不适用此延后规则。

> 格式规则：适合表格处理的数据优先用 **Excel (.xlsx)**（如号码清单、法律状态核验、检索策略与日志）；含大量文本引用的 Claim Chart 用 **Markdown**。最终附件默认仅号码清单和报告，不要求下载或本地保存 PDF。

| # | 交付物 | 必/可选 | 格式 | 说明 |
|:--:|--------|:--:|------|------|
| D1 | **检索报告** (`report.md`) | ✅ 必 | MD | 含10项标准内容；明确标注"不构成法律意见，建议由专利律师复核" |
| D2 | **风险 Claim Chart** | ✅ 必 | MD 表格 | 按全部技术特征原则逐特征对比产品规格 vs 权利要求；标注风险等级 🔴🟡🟢⚪ |
| D3 | **法律状态核验记录** | ✅ 必 | Excel (.xlsx) | 每件风险专利：公开号、法律状态（有效/审查中/失效/届满）、当前有效权利要求文本确认、核验渠道、核验日期 |
| D4 | **检索策略与日志** | ✅ 必 | Excel (.xlsx) | Sheet 1「检索策略」：检索块设计、分类逆引き、全球统一式、benchmark 验证；Sheet 2「检索日志」：每次执行的检索式全文、DB、命中数、日期、执行者、结果文件 |
| D5 | **号码清单** | ✅ 必 | Excel (.xlsx) | 含公开号、题目、权利判断地域、风险等级、法律状态、核验 DB 与日期 |
| D6 | **权利判断地域 vs 覆盖地域声明** | ✅ 必 | MD | 明确区分"仅对X国作权利判断"与"六法域文献检索覆盖"，附用户确认记录 |
| D7 | **审查中申请的处理说明** | ✅ 必（如存在） | MD | 列出审查中申请、可能授权范围预估、建议的监视周期 |
| D8 | 外观设计风险分析 | ⚪ 条件必 | MD | 产品外观可能落入外观设计保护范围时提供 |
| D9 | SDI 定期监视建议 | ⚪ 可选 | MD | 对审查中申请和即将届满专利的监视检索式与频次 |

## 七、常见错误

1. ❌ **未区分六法域覆盖与权利判断地域** → 在日本发现的专利被直接用于中国 FTO 结论
2. ❌ **未核验法律状态就将专利列为风险** → 该专利可能已因未缴年费而失效
3. ❌ **忽略审查中的专利申请** → 审查中的申请可能在未来授权并构成风险
4. ❌ **仅对比独立权利要求，忽略从属权利要求** → 从属权利要求的更窄范围也可能覆盖产品
5. ❌ **忽视权利要求的文字范围大于实施例** → 实施例未描述但权利要求字面覆盖的也算覆盖
6. ❌ **遗漏外观设计** → 产品外观可能落入外观设计专利的保护范围
7. ❌ **以法律意见口吻写报告** → FTO 报告必须声明"不构成法律意见"
