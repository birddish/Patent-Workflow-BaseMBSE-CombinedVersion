# MBSE 模型驱动检索指南

> **定位**：可选增强模块。在工程1的技术特征分解之后，可用轻量 MBSE 三视图模型更系统地驱动后续检索策略构建和证据追溯。不替代现有关键词+分类方法，而是提供结构化的模型视角来增强检索的覆盖性和可追溯性；模型不自行产生法律结论。
>
> **委托声明**：MBSE 三视图建模（F/S/B）的核心工作委托给 `MBSE 视图` 内部视图（`mode=search`）执行，其完整工作流参见该技能的 `references/modes/mode-search.md`。本文件保留检索专属的补充内容：六语关键词展开规则和分类自动提示规则。
>
> **前置要求**：必须先完成 [stage-templates.md](stage-templates.md) 工程1的基本技术特征分解。MBSE 建模在此基础之上扩展。

## 二、三视图建模方法

### 2.1 功能视图（Functional View）

**回答的问题**：系统/发明**做什么**？实现哪些功能？产生什么效果？

**建模表格**：

| 功能ID | 功能名称 | 功能描述              | 输入           | 输出          | 性能指标     |
| ------ | -------- | --------------------- | -------------- | ------------- | ------------ |
| F1     | 能量转换 | 将A能转换为B能        | A能源          | B能输出       | 转换效率>90% |
| F2     | 温度控制 | 将工作温度维持在X范围 | 温度传感器信号 | 加热/冷却指令 | ±1°C精度   |
| F3     | ...      |                       |                |               |              |

**→ 映射为检索块**：

- 功能名称/描述 → 中文、英文、日文、韩文、法文、德文功能关键词
- 性能指标 → 可选 AND 限定块（数值范围/比较）
- 输入/输出 → 上下游技术领域扩展词

**适用模式**：四种模式通用。在专利态势分析中，功能视图用于定义技术边界。

### 2.2 结构视图（Structural View）

**回答的问题**：系统/发明**由什么组成**？各组件之间的关系是什么？

**建模表格**：

| 组件ID | 组件名称 | 类型     | 材料/规格       | 连接/接口        | 所属子系统 |
| ------ | -------- | -------- | --------------- | ---------------- | ---------- |
| C1     | 转子     | 旋转体   | 永磁材料(NdFeB) | 与C2通过轴承连接 | 电机       |
| C2     | 定子     | 固定体   | 硅钢片叠层      | 与C1电磁耦合     | 电机       |
| C3     | 控制器   | 电子单元 | MCU+DSP         | 与C1、C4电连接   | 控制系统   |
| C4     | ...      |          |                 |                  |            |

**→ 映射为检索块**：

- 组件名称 → 中文、英文、日文、韩文、法文、德文结构关键词
- 材料/规格 → 可选材料块（AND）
- 连接/接口 → 邻近运算符组合（如 `转子 ADJ3 轴承`）
- 组件类型 → IPC/CPC 分类提示（旋转体→F16C、电子单元→H05K）

**适用模式**：查新检索、无效检索、FTO 均适用。专利态势分析可选（用于分类分布分析）。

### 2.3 行为视图（Behavioral View）

**回答的问题**：系统/发明**如何运作**？步骤流程是什么？各状态如何切换？

**建模表格（方法/流程）**：

| 步骤ID | 步骤名称 | 前置步骤 | 后续步骤 | 执行条件   | 并行/串行  |
| ------ | -------- | -------- | -------- | ---------- | ---------- |
| S1     | 初始化   | —       | S2       | 上电信号   | 串行       |
| S2     | 参数检测 | S1       | S3, S4   | S1完成     | 串行→并行 |
| S3     | 主处理   | S2       | S5       | 检测正常   | 与S4并行   |
| S4     | 异常处理 | S2       | S5       | 检测异常   | 与S3并行   |
| S5     | 结果输出 | S3, S4   | —       | S3或S4完成 | 串行       |

**→ 映射为检索块**：

- 步骤名称 → 中文、英文、日文、韩文、法文、德文方法关键词
- 前置/后续关系 → 邻近运算符或时间顺序限定
- 并行/条件分支 → 可选 AND/OR 组合逻辑

**适用模式**：主要用于涉及方法权利要求的查新检索和无效检索。FTO 中用于产品制造/使用方法的侵权分析。

## 四、模型追溯矩阵（工程4使用）

MBSE 的核心价值之一是**全流程追溯**。在工程4的对比分析阶段，使用追溯矩阵将每件核心文献的公开内容反向映射到模型要素：

| 模型要素         | 检索式编号 | 命中文献            | MCP证据位置      | 覆盖判定    |
| ---------------- | ---------- | ------------------- | ---------------- | ----------- |
| F1（能量转换）   | Q1, Q3     | D1: JP2020xxxxxxA   | ¶[0015]–[0020] | ✅ 充足     |
| F1（能量转换）   | Q1, Q3     | D2: US10,xxx,xxx B2 | col.5 l.30–50   | ✅ 部分充足 |
| C1（转子+材料）  | Q2         | D1: JP2020xxxxxxA   | ¶[0025], 图2    | ✅ 充足     |
| C2（定子）       | Q2         | —                  | —               | ⚠️ 未发现 |
| S3（主处理步骤） | Q4         | D3: CNxxxxxxxxxB    | ¶[0040]–[0055] | ✅ 充足     |

**追溯矩阵的价值**：

- 快速定位哪些模型要素已有证据覆盖、哪些是空白
- 空白要素 → 提示需要补充检索或调整检索策略
- 覆盖充分的要素 → 支撑最终结论的可信度

追溯矩阵中的“覆盖”只表示候选证据的技术要素对应，必须再进入专利证据包的 `NB` 或 `IS`：前者严格限于一篇文献，后者记录最接近现有技术、区别特征、技术效果和组合启示。相似度或关键词命中不得替代原文定位。

## 八、常见问题

**Q: MBSE 建模是否增加了工作量？**
A: 对于简单案件，MBSE 建模的收益不大，可以跳过。对于涉及多组件、多功能、多步骤的复杂系统（如机电一体化产品、通信协议、制造工艺），MBSE 建模前期多花 15–30 分钟，可在工程2和工程4分别节省检索式构建和证据定位的时间，且显著降低漏检风险。

**Q: 模型要素和技术特征是什么关系？**
A: 技术特征是法律/专利视角的分解（用于与权利要求对比）；MBSE 模型要素是工程/系统视角的分解（用于驱动检索覆盖）。两者互补：MBSE 覆盖可能超出权利要求字面范围的技术细节，有助于发现更广泛的现有技术。

**Q: 是否必须使用专业 MBSE 工具？**
A: 不。本指南的"MBSE"是方法论层面的轻量适配，所有建模均使用 Markdown 表格完成，无需任何外部工具。
