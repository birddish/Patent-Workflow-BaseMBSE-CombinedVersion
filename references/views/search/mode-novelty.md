# 查新检索模式指南

> **适用场景**：评估发明方案相对于全球已公开文献的新颖性与创造性，为专利申请决策提供依据。
> **共用基础**：本文件仅含本模式特有内容。通用流程、模板和验证门详见 [stage-templates.md](stage-templates.md) 和 [search-guide.md](search-guide.md)。

---

## 一、模式速查

| 维度 | 本模式设定 |
|------|-----------|
| **调查对象** | 计划申请的发明技术方案 |
| **分解对象** | 发明的技术特征 |
| **权利状态限定** | 无——失效、撤回、驳回、公开中的全部文献均可作为现有技术 |
| **筛选视角** | 寻找与发明特征相同或类似的公开内容 |
| **评价形式** | 核心文献 → 技术特征对比表 + 新颖性卡/创造性卡 + X/Y/A 候选分类 |
| **最终产出** | 对新颖性/创造性的初步判断 + 核心对比文献清单 |

---

## 二、适用验证门

> 推进规则：下表的覆盖性要求适用于正式报告的完整覆盖表述。首次运行只需完成一次语法、范围和基准日检查并保存原始结果；benchmark 未命中登记为补检/限制，不阻断核心文献核验。

| 验证门 | 适用？ | 说明 |
|--------|--------|------|
| ① 实存 | ✅ | 所有列入成果的公开号/专利号须经书目核验 |
| ② 覆盖性 | ✅ | 六语全球统一式覆盖 CN/US/JP/KR/EP/WO/PCT，已知 benchmark 必须被检索式命中 |
| ③ 对比 | ✅ | 核心文献须通过 MCP/可信全文定位到具体段落/权利要求/附图 |
| ④ 法律状态 | ❌ 不适用 | 失效文献同样是有效现有技术，无需核验法律状态 |
| ⑤ 强度 | ✅ | 避免断定"具有新颖性""具有创造性"，改用"未见相同/类似公开"等限定表述 |

## 三、各阶段模式差异

### 工程1 — 检索方案设计

- **分解对象**：发明方案的技术特征。按结构/步骤/功能/效果进行特征拆解。
- **基准日**：通常为实际申请日或优先权日。如尚未申请，以当前日期为基准日（注意：后续公开日在基准日之后的文献不构成现有技术）。
- **不需要**：权利状态限定、FTO 权利判断地域。

### 工程2 — 检索策略

- 与通用流程一致，无模式特殊要求。
- 已知 benchmark 文献的选取：优先找与发明最接近的已知文献 2~5 件。

### 工程3 — 正式检索与筛选

- **筛选视角**：寻找与发明特征"相同"或"类似"的公开。注意区分"相同公开"（影响新颖性）与"类似公开"（可作为组合影响创造性）。
- 与通用流程一致。

### 工程4 — 对比分析（核心差异）

#### 4.1 技术特征对比表

对每件核心文献制作特征级对比：

| 技术特征 | 文献X公开位置 | 4值判定 | 依据 |
|----------|-------------|---------|------|
| A | ¶[0023] | 充足/部分充足/不充足/无法判定 | 说明匹配或差异 |

#### 4.2 X/Y/A 候选分类与判断卡

> 本节只适用于 `delivery_profile=formal`。`quick/standard` 只输出候选、核心候选、背景线索或待核验，不填写 X/Y/A、NB 或 IS。

| 等级 | 定义 | 赋值条件 |
|------|------|---------|
| **X** | 单文献核心候选 | 基于可信全文，对每项权利要求分别填写单文献 `NB`；新颖性和创造性观察不得合并 |
| **Y** | 组合分析候选 | 文献可能补足区别特征；必须填写 `IS` 的技术启示、结合动机、兼容性和合理成功预期 |
| **A** | 仅表示技术背景/水平 | 文献属于相同技术领域但差异显著，仅作背景参考 |

> ⚠️ 仅有号码或摘要的文献不得赋予 X/Y。X 不是“当然否定新颖性或创造性”；只有单一文献覆盖全部必要特征且满足公开证据要求时，才在 `NB` 中记录高新颖性风险。Y 不能仅以“公知常识”补足，须有对应证据。

#### 4.3 判断卡

对每项候选权利要求建立：

1. **新颖性判断卡（NB）**：一项权利要求对一篇基准日前文献逐特征比对；不得组合多篇文献。
2. **创造性三步法判断卡（IS）**：最接近现有技术、区别特征及效果、实际技术问题、第二文献/公知常识的启示与结合可行性。

字段、状态和结论强度遵循 `../mbse/patent-evidence-pack.md`。未检得只能表述为记录检索范围内“未见”，不构成肯定式可专利性结论。

### 工程5 — 报告书

- **结论限定表述示例**：
  - ✅ "在本次检索范围内，未见单独公开全部构成要件的文献"（新颖性）
  - ✅ "文献 D1–D3 的组合可能对创造性提出质疑，建议进一步评估"（创造性）
  - ❌ "本发明具有新颖性和创造性"（断定表述，禁止）

## 四、模式专属审查要点

独立审查时，除 [review-prompt.md](review-prompt.md) 通用审查项外，追加以下检查：

| # | 检查项 | 严重度 |
|---|--------|--------|
| N1 | 是否正确应用了 X/Y/A 候选分类？号级/摘要级文献是否被错误赋予 X/Y？ | CRITICAL |
| N2 | 技术特征分解是否覆盖发明的全部技术特征？遗漏特征会导致新颖性误判 | CRITICAL |
| N3 | benchmark 文献是否确实与发明技术领域相关？ | HIGH |
| N4 | "充足"判定的文献是否确实公开了对应技术特征（而非推断或暗示）？ | HIGH |
| N5 | 是否误将法律状态门应用于本模式（如以专利失效为由排除文献）？ | MEDIUM |
| N6 | 结论是否使用了断定表述（"具有新颖性""可以授权"等）？ | HIGH |
| N7 | NB 是否严格限于单一文献？IS 是否记录了技术问题、结合动机、兼容性和成功预期？ | CRITICAL |

## 六、交付物清单

> `quick/standard` 使用 [delivery-profiles.md](delivery-profiles.md) 的最小交付，D3 及完整工作簿仅在 `formal` 必需。

> 阶段2–4可先以最小 Markdown 运行记录保存检索式、数据库、命中数、日期、结果文件及异常状态；本节列示的 Excel 策略与日志在工程5报告定稿前统一完成。

> 格式规则：适合表格处理的数据优先用 **Excel (.xlsx)**（如号码清单、检索策略与日志）；含大量文本引用和技术对比的用 **Markdown**。最终附件默认仅号码清单和报告，不要求下载或本地保存 PDF。

| # | 交付物 | 必/可选 | 格式 | 说明 |
|:--:|--------|:--:|------|------|
| D1 | **检索报告** (`report.md`) | ✅ 必 | MD | 含10项标准内容；结论用"未见相同/类似公开"等限定表述 |
| D2 | **技术特征对比表** | ✅ 必 | MD 表格 | 每件核心文献逐特征标注 4 值判定 + MCP 证据位置 |
| D3 | **新颖性/创造性判断卡与 X/Y/A 候选表** | ✅ 必 | MD + JSON | NB 按单文献填写；IS 按三步法填写；号级/摘要级文献单独列"待核验" |
| D4 | **检索策略与日志** | ✅ 必 | Excel (.xlsx) | Sheet 1「检索策略」：检索块设计、分类逆引き、全球统一式、benchmark 验证、法域拆分判定；Sheet 2「检索日志」：每次执行的检索式全文、DB、命中数、日期、执行者、结果文件 |
| D5 | **号码清单** | ✅ 必 | Excel (.xlsx) | 含公开号、题目、证据等级、核验 DB 与日期 |
| D6 | **六法域覆盖核验表** | ✅ 必 | MD 表格 | CN/US/JP/KR/EP/WO 逐一标注覆盖状态 |
| D7 | benchmark 验证记录 | ⚪ 可选 | MD（已含于 D4） | 如有已知文献，记录命中验证结果 |
| D8 | 公知常识佐证文献 | ⚪ 可选 | 号码列表 | 仅在 Y 等级引用公知常识时提供 |

## 七、常见错误

1. ❌ **将失效专利排除在检索范围外** → 失效专利同样是有效的现有技术证据
2. ❌ **仅检索相同技术方案，忽略类似方案的组合可能性** → 创造性评价需要考察组合
3. ❌ **对摘要级文献直接给出 X/Y 或法律判断** → 必须先通过 MCP 全文核验
6. ❌ **以多文献拼接否定新颖性，或缺少动机即断定组合显而易见** → 分别使用 NB 和 IS，保留证据缺口
4. ❌ **技术特征分解过于笼统** → 一个特征包含多个技术点时，应进一步拆分
5. ❌ **忽略公知常识的举证** → Y 等级引用公知常识时，建议另附公知常识文献
