# 输出检查清单

在定稿审查意见答复或复审意见陈述书之前（所有 mode 通用）：

## 权利要求与修改

- 以最新的权利要求文本或替换页为准。
- 草稿中引用的修改后权利要求文本与用户最新文本一致。
- 每项修改在原权利要求书/说明书/附图中均有支持依据。
- 用户更正后，无旧版权利要求措辞残留。
- 新版 `CLM` 已记录 `supersedes`，并以新版本重算必要特征、区别特征、实际技术问题和创造性路径。
- 每项修改已说明保护范围的扩大/缩小/不变与需否客户确认。

## 论证逻辑

- 在反驳之前准确概括了审查员的驳回理由和组合路径。
- 已按“审查员断言→证据段落→区别/效果→CombinationPath→申请人行动→结果理由”完整回放，不能只写“D1+D2”。
- 区别特征分组遵循用户指定的顺序（如有）。
- 在适当时将区别特征作为整体技术手段（mechanical: 机械配合；biochemical: 组分/工艺协同；electronic-communication: 模块/数据流协同）进行论述。
- 实际解决的技术问题具体且与修改后的权利要求挂钩。
- 对比文件批评与权利要求区别特征相关联，而非游离的批评。
- 因果关系正确：问题 → 方案需求 → 技术关系 → 效果。
- 审查意见每个问题均已选择认可/争辩/修改/删除/分案/补充核验/客户确认之一作为主处理动作。
- “组合不可行”的论证已检查常规可允许变换，并说明为何仍需二次设计或缺少成功预期。
- 节点覆盖、关系/行为保持和因果闭合已分层核验；`FusionFeasible` 仅作为工程事实，不直接替代法律结论。
- 每项技术效果均有 `EffectEvidenceCard`，载明比较基准、来源日期、因果路径和权利要求范围覆盖。

## 域特定检查

- **Mechanical**：草稿在相关处解释了相对位置、连接、运动、接触、受力路径、导向/限位关系、传动或装配顺序。没有过度夸大无支持的尺寸、受力、效率或可靠性效果。基于附图的推论措辞审慎。
- **Biochemical**：草稿在相关处解释了组分关系、反应路径、工艺条件依赖性和结构-性能关系。含量范围和端点值有实施例支撑。组分相容性和工艺条件冲突已论证。
- **Electronic-Communication**：草稿在相关处解释了数据流、信号处理链、算法-硬件交互关系。技术性链条（输入数据→算法处理→输出数据→技术效果）完整。术语已转换为技术表述。

## 形式输出

- 采用客观、简洁的中国专利代理师行文风格。
- 段落和权利要求引用具体明确。
- 答复开头只写明针对第几次审查意见/哪一份决定及发文日；缺失日期时明确标记待核验，不自行补齐。
- 每个问题标题直接表达审查员提出的问题，且问题内部按“审查意见原文→本申请文本原文→对比文件原文→认知错误或论证缺口→回应/修改→处理结果”组织。
- 每个实质性事实或法律论点均在正文中直接粘贴必要原文；不存在只有 D1/D2、页码、段落号、路径或文件名的 `citation-only` 段落。
- `ArgumentOnly` 不设置独立的当前权利要求总览，也不出现修改后权利要求；相关当前权利要求原文只放在对应问题下。
- `AmendmentBased` 只在对应问题下直接呈现修改后的权利要求和原始支持；未通过重算门时不得生成对外定稿。
- MBSE 符号已从最终法律行文中移除。
- 事实核实编号、组合路径编号、证据状态和证据包 ID 已从对外答复中移除，只保留于内部追溯材料。
- `ArgumentOnly` 与 `AmendmentBased` 已分流；补正后的旧分析、旧效果和旧答复追溯已失效或待重算。
- `DecisionTrail` 可从审查意见正向走到结果，也可从结果理由反向走回证据段落。
- 从属权利要求讨论不重复已纳入权利要求1的特征。
- 首先生成 Markdown，除非用户明确要求 DOCX。

## 双重就绪性

- `content_status` 与 `submission_status` 已分别评定，没有用“审计通过”替代两者。
- 对比文件日期/资格、核心原文、支持依据中存在 `Q` 时，内容状态未标为 pass。
- 提交期限、申请人/代理信息、替换页/签章、范围取舍中存在未确认项时，提交状态为 blocked。

## 普通版 v2.1-oa 交付文件

新交付按以下角色各生成一个正式文件；旧编号文件名仅作为只读兼容别名：

```text
00-交付说明.md
01-准入与证据边界.md
02-事实核实审计.md
03-追溯链与技术启示分析.md
04-权利要求与修改说明.md
05-审查意见答复或复审意见陈述.md
06-答复追溯报告.md
07-问题—处理动作矩阵.md
08-模型到答复追溯报告.md
09-质量审计与提交状态.md
run-metadata.json
patent_evidence_pack.json
```

活动快照应以 `snapshot_id + freeze_revision` 冻结；新交付不生成Hash。对外文件不得包含内部对象ID、节点符号、状态标签或模型评分。
