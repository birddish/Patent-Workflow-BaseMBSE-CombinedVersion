# 机械/结构域答审规则

## 适用范围和边界

本文件供 答审/复审视图 的 mechanical mode 使用，覆盖机械结构、装置、机构、传动、支撑、导向、密封、定位、夹持、输送和制造设备案件。

本文件只规定机械技术事实、MBSE 建模和答复措辞，不承载论文综述或治理制度。ME-01 至 ME-06、MechanicalCooperationCheck、CombinationPath、TeachingRecord 和 EffectEvidenceCard 均为工程分析接口，不是法律结论。pass、Q、fail、blocked 仅表示资料和模型状态。

## 机械 S 节点与关系

| 节点/关系 | 最少记录内容 | 典型审查争点 |
|---|---|---|
| 构件/组件 | 零件、部件、组件、装配层级和附图标记 | 是否真正公开该构件 |
| 连接关系 | 固定、活动、铰接、焊接、螺纹、卡接、传动连接 | 是否可任意替换 |
| 位置关系 | 同轴、平行、垂直、内外、相邻、包围、前后 | 空间约束是否相同 |
| 配合/接触 | 啮合、贴合、间隙、过盈、滚动、滑动、密封接触 | 接触条件是否相同 |
| 运动关系 | 转动、平动、摆动、往复、连续、间歇、复合运动 | 运动行为是否等同 |
| 受力关系 | 动力源、驱动件、传递件、受力点、约束反力、输出件 | 受力路径是否保持 |
| 状态关系 | 初始、触发、中间、锁止、释放和终止状态 | 状态转换是否公开 |
| 接口参数 | 尺寸、角度、节距、间隙、模数、孔距、压缩量 | 参数是否受匹配关系约束 |
| 装配/工艺 | 装配顺序、安装基准、调整条件和加工关系 | 是否为必要限定 |

构件名称、用途或外观相近，不等于结构、关系、行为和效果相同。附图只能支持其明确表达的结构或关系，不能仅凭比例推断尺寸、材料、受力方向或运动顺序。

## 机械 R/F/S/B/E 最小链

机械方案至少建立：

~~~text
R 技术问题
  → F 所需功能
  → S/REL 构件及结构关系
  → B/STATE 受力、运动和状态转换
  → E 技术作用或效果
~~~

涉及传动、驱动、支撑、夹持、密封、导向、变形或锁止时，必须回放：

~~~text
主动力源
  → 驱动单元
  → 接触/啮合区域
  → 传递单元
  → 被驱动件
  → 约束/反力
  → 运动或状态输出
  → 技术效果
~~~

“到达某一位置”不能替代行为、状态和效果；结构名称不能直接证明稳定性、低磨损或防泄漏。

## 模式路由和统一字段

阶段三和阶段四按以下模式路由：

| pattern_id | 适用问题 | 关键字段 |
|---|---|---|
| ME-01 | 一体化机械配合和整体协同 | 构件、关系、接触、行为、效果 |
| ME-02 | 对比文件组合不兼容 | 空间、接口、装配、工作原理 |
| ME-03 | 受力和运动路径区别 | 动力源、传递、约束、时序、输出 |
| ME-04 | 尺寸、节距、间隙和接口约束 | 基准、参数、配合和工况 |
| ME-05 | 传统替代方案不成立 | 替代操作、关系变化、效果归属 |
| ME-06 | 结构需求先于驱动/控制方式 | R→F→S/B 因果、选择方向 |

每次模式命中必须同时登记 issue_id、claim_version_id、CombinationPath、TeachingRecord 和 EffectEvidenceCard。至少记录适用性、不适用情形、D0/Dk 技术作用、操作序列、Ω、正向闭合、反向断裂、答复模式和法律转换。

## 区别特征和组合路径

机械区别特征按以下层级分组：

1. 构件或组件；
2. 连接、位置、配合和接触关系；
3. 运动、受力和状态关系；
4. 尺寸、节距、间隙、孔距、压缩量等接口参数；
5. 由结构和行为产生的技术效果。

每条 D0/Dk 路径必须记录：

- 完整技术方案和证据位置；
- 加入、替换、重连、重排或参数调整；
- 每一步的空间、装配、接触、受力和运动状态；
- 组合后是否保持各文件工作原理；
- 是否仍能产生所主张的效果；
- 技术启示、选择方向和合理成功预期。

工程上可以重新设计，不等于现有技术给出了到达路径。

## 机械组合可行性检查

机械 CombinationPath 必须检查：

- 空间是否干涉；
- 是否失去接触、啮合或支撑；
- 安装基准、孔距、轴径、节距和间隙是否匹配；
- 运动方向、自由度、行程和顺序是否冲突；
- 动力源、传递件和约束反力是否连续；
- 锁止、释放、密封或导向状态是否连续；
- 组合是否破坏原有功能或工作目的；
- 效果是否由组合后的结构—行为链解释。

## 从属权利要求和多项从属

- 从属权利要求先沿每一条合法 DepPath 展开全部继承限定，再识别新增限定；
- 多项从属按每条择一引用路径分别建模，不取并集；
- 兄弟从属分支不能泄漏到当前路径；
- 新增机械限定必须有继承锚点，并连接到结构、关系、行为或效果链；
- 已并入独立权利要求的特征不能再次作为从属权利要求的独立贡献；
- 修改后必须重新绑定当前 ClaimVersion、SupportLink、CombinationPath 和 ResponseTrace。

## 五类答复争点

| 争点 | mechanical mode 的处理 |
|---|---|
| 事实认定错误 | 核对是否把未公开连接、配合、尺寸、受力或状态写成对比文件内容 |
| 设计事项认定错误 | 说明空间、接口、受力、运动和工作原理是否共同约束选择 |
| 缺乏结合动机 | 回放 D0/Dk 目的、改造方向、必要改造和成功预期 |
| 存在阻碍因素 | 说明干涉、失去接触/支撑、运动冲突、参数不匹配或原理破坏 |
| 有利/意外效果 | 以结构—行为—状态—效果链、比较基准和范围覆盖为依据 |

最接近现有技术只有在会改变区别特征、实际技术问题、组合方向、效果归属或成功预期时才作为主争点。

## MechanicalCooperationCheck

含有两组以上区别特征时，另行检查：

- 各组特征是否共享安装基准、接口、受力路径、运动状态或控制对象；
- 特征关系是简单并列、局部替换还是整体协同；
- 删除任一组后，结构、行为和效果是否仍能独立实现；
- 效果是否有完整机械方案的比较基准；
- 从属路径是否保持分支隔离。

该检查不直接产生创造性法律结论。

## 机械域效果和证据卡

EffectEvidenceCard 至少记录：

- effect_id、受影响对象和客观指标；
- 结构/关系/行为原因；
- 比较基准、工作条件、测量方法和范围覆盖；
- 原始申请文件、实施例或对比例位置；
- 申请日可得性和 D/I/Q 状态。

没有比较基准、工况或原始支持时，应使用“提供结构基础”“适于保持”“可能减少风险”等审慎表述。

## ArgumentOnly 与 AmendmentBased

- ArgumentOnly：保持 ClaimVersion 不变，只回应事实、区别、效果、结合动机、阻碍因素或路径断点。
- AmendmentBased：新建 AmendmentEvent 和 ClaimVersion，重新生成 TA、NB、CombinationPath、Δ*、EffectEvidenceCard 和 ResponseTrace；旧分析标记失效或待重算。
- 未通过 recalculation_gate 时只能输出内部条件性稿件。
- 对外稿不得出现 ME 编号、R/F/S/B/E、D/I/Q/X、CombinationPath 或治理字段。

## 机械域常见陷阱

- 零件名称相同不等于结构关系相同；
- 附图相邻不等于连接或配合已公开；
- 仅凭图形比例不能确定尺寸和间隙；
- 存在传统替代件不等于具有替代动机；
- “更稳定”“低磨损”“避免泄漏”必须有结构—行为—效果证据；
- 受力或运动术语差异不能自动推出创造性；
- FusionFeasible=false、模型相似度或模式命中不是法律结论。
