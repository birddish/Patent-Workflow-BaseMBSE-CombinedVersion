# 内部模板：直接内容证据表

本模板只用于把 JSON 中已经嵌入的实际内容整理成可复核的证据单元，不负责从 `path`、`location`、`source_file`、`source_ref` 或 `source_trace` 读取外部文件。

## 一、直接内容单元

| 字段 | 内容 |
|---|---|
| 证据单元编号 | 【内部编号】 |
| 证据类型 | OA / 决定 / 权利要求 / 对比文件 / 申请支持 / 答复 / 效果 |
| 对应问题 | 【具体问题标题】 |
| 对应权利要求 | 【修改后的权利要求号；ArgumentOnly 时填必要的相关权利要求】 |
| 原文摘录 | 【直接粘贴足以理解论点的完整句子或连续段落】 |
| 来源定位 | 【页码、段落、图号或 JSON 字段；仅作复核】 |
| 原文明确记载 | 【根据原文逐项归纳】 |
| 原文未记载/不能直接得到 | 【具体列出】 |
| 与本申请文本的关系 | 一致 / 部分一致 / 不一致 / 无法核验 |
| 与审查员主张的关系 | 支持 / 不支持 / 部分支持 / Q |
| 可使用表述 | 确定性 / 受限 / 条件性 / 不使用 |

## 二、问题论证单元

每个具体问题依次填写：

```markdown
### 【存在的问题：审查员关于……的认定】

#### 审查意见原文

> 【直接粘贴】

#### 本申请文本如何记载

> 【直接粘贴修改后的权利要求或申请文件原文】

#### 对比文件如何记载

> 【直接粘贴对比文件原文】

#### 审查员认知错误的具体内容

【逐项说明将哪一段原文误读、扩大或拼接，以及忽略了什么限定。】

#### 申请人回应或处理动作

【争辩、修改、删除、核验或客户确认。】

#### 处理结果

【确定结果或 Q/conditional/blocked。】
```

## 三、直接摘录完整性检查

- [ ] 保留对象、限定条件、范围端点、步骤顺序、连接关系和例外；
- [ ] 没有只复制一个名词，再用推测补成完整方案；
- [ ] 没有用省略号省略区别特征、否定表达或因果关系；
- [ ] 原文后紧跟分析，读者不需要跳转到其他文件才能理解；
- [ ] 空内容已标记“原文未提供/待核验”；
- [ ] 数据集 ID、任务 ID、申请号样式和案例编号没有被当作法律事实。
