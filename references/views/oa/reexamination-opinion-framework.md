# 复审意见陈述分析框架

本文件只负责复审阶段的决定理由回放、技术问题分析和内部审计，不承载对外正文模板。形成对外《复审意见陈述书》时，另读取 `templates/external/reexamination-statement.md`；如发生补正，再读取 `templates/external/amendment-explanation.md` 和 `templates/internal/claim-version-recalculation-sheet.md`。

## 1. 来源审查清单

起草前，提取以下信息：

- 驳回决定日期、被驳回的权利要求、引用对比文件及法律依据；
- 审查员选定的最接近现有技术及所主张的组合路径；
- 最新独立权利要求文本及修改后的从属权利要求；
- 每项修改的原始申请支持依据；
- 说明书中描述技术问题、技术效果和关键实施例的段落；
- 用户提供的优选论点、特征顺序和措辞约束。

若最新权利要求文本与之前的替换页或先前草稿冲突，以最新用户指令为准，并据此更新所有后续推理。

复审文书内部应建立 `DecisionTrail`，把驳回决定的理由反向连接到申请人答复、`OAIssue`、`CombinationPath` 和证据段落；若复审阶段补正，按 `AmendmentBased` 新建 `ClaimVersion` 并重新执行实体模型，不能沿用修改前的区别链或效果判断。

## 2. 修改说明

陈述：

1. 已纳入独立权利要求的内容；
2. 修改在原始申请中的支持位置；
3. 修改未超出原始公开范围，符合专利法第三十三条的规定。

使用审慎的支持措辞：

- "上述修改可由原说明书……及原权利要求……直接得到。"
- "该修改未超出原申请文件记载的范围。"

避免：

- 依赖说明书中未公开的效果；
- 引用未经源文件核实的段落编号；
- 在用户提供新版后仍使用旧版权利要求。

## 3. 实际解决的技术问题

不要将问题表述为"提高稳定性"或"实现驱动"等泛化目的。使用与修改后权利要求挂钩的具体问题。

推荐模式：

> 基于上述区别技术特征，修改后权利要求实际解决的技术问题应当表述为：在……工况/结构条件下，如何通过……实现……，并避免/减少……。

当分组后的区别特征存在因果关系时，明确陈述因果链条：

> A路径条件 → B结构需求 → C驱动/控制限制 → D采用权利要求中的具体结构 → E技术效果。

## 4. 区别特征分组

按照修改后权利要求的技术逻辑对区别特征进行分组。若审查员的分组方式割裂了一体化的技术路线，则不受其分组方式的限制。

分组示例（以机械分拣设备复审为例）：

1. 内外圆弧：机架/轨道具有内圆弧和外圆弧，且滚轮设置于对应轨道内。
2. 板链部分：第一传动板、第二传动板、第一滚轮、第二滚轮及铰接关系。
3. 摩擦驱动单元：皮带、主动轮、从动轮、压带轮，以及皮带外侧壁贴合传动板侧面。

当用户指定顺序时，在以下部分保留该顺序：

- 技术问题；
- 区别特征列表；
- 各评价小节；
- 最终结论。

## 5. 非显而易见性撰写模式

对每组区别特征：

1. 陈述权利要求特征；
2. 说明其在修改后权利要求的技术路线中的作用；
3. 比较引用对比文件的教导；
4. 说明缺少教导、不兼容或缺乏动机；
5. 回归整体组合。

适当时使用"关于区别技术特征一/二/三"标题。

## 6. 兼容性与受力路径分析

当现有技术使用齿轮/链条、链轮/链条、拨爪/链条、齿条/齿轮或离散啮合时：

- 识别节距、齿距、拨爪间距、啮合点或链节间隔约束；
- 说明链节/单元尺寸受啮合关系约束；
- 分析非直接驱动链节如何通过相邻链节受力；
- 区分被牵引的链节与在接触面接受摩擦力的板单元；
- 解释为何仅在传统链条上增加摩擦驱动可能无法解决几何或路径问题。

常用表述：

> 齿轮链条式传动要求被驱动单元按照固定节距排列，并要求啮合位置与齿距、链节节距或拨爪间距相匹配。

> 摩擦驱动只改变动力输入方式，并不会改变短节链节在内凹圆弧处连续收拢的几何关系。

> 若被驱动对象仍是传统短节链条，非直接处于摩擦接触区域的链节仍主要依靠相邻链节牵引传力。

## 7. "可以做大的"——避免无支持的扩大化

当权利要求记载了板件但未记载明确尺寸时，不要说权利要求"限定了较大尺寸"，除非确有任何文字如此记载。

推荐表述：

- "需要一种可以做大的传动单元"；
- "第一传动板和第二传动板提供形成较大板状传动单元的结构基础"；
- "相对于受节距约束的短节链环结构，该板状结构更适合作为可做大的传动单元基础"；
- "该表述用于说明技术路线，并非额外增加尺寸限定。"

避免：

- "本申请限定单个传动板很大"；
- 案卷中不存在的精确尺寸断言；
- 将推断的设计优势作为未记载的权利要求限定。

## 8. 从属权利要求

在独立权利要求的创造性确立之后：

- 陈述从属权利要求范围更窄，因此同样具备创造性；
- 仅对审查员单独质疑的从属权利要求添加简短的技术作用说明；
- 检查修改是否已将某项从属特征纳入权利要求1。若是，则不应将其作为该从属权利要求的独立贡献重复论述。

## 9. 最终审计

定稿前：

- 最新权利要求文本准确引用；
- 无旧版特征措辞残留；
- 区别特征顺序与用户指令一致；
- 每项修改均有支持依据；
- 最终意见陈述书中未使用 MBSE 符号替代技术语言；
- 对比文件批评与权利要求区别特征挂钩；
- 除非用户要求或确认，不生成 DOCX。
