# MBSE 模型到新颖性/创造性的映射方法论

> **适用边界**：本文件将 MBSE 用作事实组织和工程分析工具，不取代中国专利法或审查指南。新颖性必须按“单一文献 × 全部必要权利要求特征”核验；创造性必须先核实最接近现有技术、区别特征、技术效果和实际技术问题，再评估技术启示、结合动机、兼容性及合理成功预期。详细字段以 `../mbse/patent-evidence-pack.md` 为准。

## 1. 理论基石：MBSE 五层模型与专利三性的对应关系

### 1.1 专利性判断的本质

在 MBSE 视角下，一项技术方案（权利要求）可以表示为一条或多条完整的追溯链：

```
C = {Rᵢ → Fⱼ → Sₖ → Bₗ → Eₘ}
```

其中每个节点代表：

| 层级 | 符号 | 含义 | 专利法对应概念 |
|------|------|------|--------------|
| R | Requirement | 技术问题（"如何……"） | 发明要解决的技术问题 |
| F | Function | 功能（"实现……功能"） | 技术方案要实现的功能目的 |
| S | Structure | 结构/组分/步骤（物理实体及关系） | 技术特征（权利要求所记载的结构、组成、步骤） |
| B | Behavior | 行为/过程（结构如何运作） | 技术手段的工作方式、运动/受力/反应过程 |
| E | Effect | 技术效果 | 发明所达到的技术效果 |

### 1.2 新颖性判断的 MBSE 形式化

**定义（新颖性的 MBSE 表述）**：

> 一项权利要求可能面临新颖性风险，只有在存在**单一**对比文件 D，且该文献按 `NB` 卡对全部必要 `CF` 完成明确或必然隐含披露核验时才可记录。R/F/S/B/E 用于定位事实和检查关系，不能代替逐项权利要求特征比对。
>
> **S 覆盖条件**：∀ Sᵢ ∈ C_claim，∃ Sⱼ' ∈ C_D 使得 Sᵢ 的技术内容（结构特征及其结构关系）被 Sⱼ' 完整公开。
>
> **可推导条件**：在上述 S 覆盖成立的前提下，C_D 的 R/F/B/E 节点可由覆盖的 S 节点集合按本领域常规知识自然推导，且推导结果与 C_claim 的对应节点一致。

**形式化表达**：

```
不具备新颖性 ⇔
  ∃ 单一文件 D: S_claim ⊆ S_D
  ∧ 从 S_D 可自然推导出 R_claim, F_claim, B_claim, E_claim
```

**关键推论**：
- 新颖性判断的核心是 **全部必要 CF 的单一文件覆盖**；CF 可包括结构、步骤、条件、顺序、参数和必要关系，不能只以 S 节点代替。
- 如果单一文件未核验覆盖全部必要 CF，只能记录当前证据不足；不得据此断定新颖性成立。
- **S 节点的覆盖不是字面相同**，而是技术内容的实质相同。对比文件可以换一种表述方式，但只要公开了相同的结构及其结构关系，即构成覆盖。

### 1.3 创造性判断的 MBSE 形式化

**定义（创造性的 MBSE 表述）**：

> 一项权利要求的创造性风险评估以 `IS` 卡为单位，先确定最接近现有技术，再核实区别特征、效果和实际技术问题，并审查文献组合是否有技术启示、动机、兼容性和合理成功预期。
>
> **条件一（追溯链可融合）**：各文件的追溯链 C_D1, C_D2, …, C_Dn 可以通过**技术上有意义的方式**融合为一条融合链 C_fused。
>
> **条件二（融合链覆盖权利要求链）**：融合后的追溯链 C_fused 在 S 层面覆盖权利要求的全部 S 节点，且其 R/F/B/E 层面与权利要求的对应节点一致。
>
> **条件三（存在技术启示）**：本领域技术人员有动机和可行手段完成上述融合。

**形式化表达**：

```
不具备创造性 ⇔
  ∃ {D1, D2, …, Dn}, n ≥ 1:
  Fuse(C_D1, C_D2, …, C_Dn) → C_fused  ← 可融合
  ∧ Cover(C_fused, C_claim)              ← 覆盖权利要求
  ∧ Motivation({D1, …, Dn} → C_fused)   ← 有技术启示
```

**关键推论**：
- 创造性判断不能仅依据多文件追溯链的工程可融合性；融合可行性和覆盖情况是 `IS` 的工程分析子项。
- 审查意见答复应以已核验事实支持最接近现有技术、区别特征、实际技术问题或组合启示中的具体争点。
- **最常见的答复路径**：证明追溯链不可融合（融合失败）或融合链不覆盖权利要求（覆盖不足）。

为避免把法律测试误作工程生成器，本方法将 `Could-Would` 降级为下游规范接口：它只检查争点是否属于创造性评价、事实证据是否足以进入组合分析，以及技术事实是否已准备好转换为法律评价；不负责生成追溯链、判断接口兼容或证明技术效果。

## 2. 追溯链融合：条件与失败模式

### 2.1 追溯链融合的操作定义

"追溯链融合"是将多篇对比文件的节点重组为一条完整追溯链的操作。其本质是：以 D1（最接近现有技术）的追溯链为主干，将 D2, …, Dn 中的特定节点"嫁接"到主干上，替换或补充主干的对应节点。节点分别出现只构成来源分散事实，不等于同一工作系统已经可达。

每条可审计路径统一登记为：

```text
CombinationPath = <D0, {Dk}, operations, Ω, interface/parameter conditions,
                     TeachingRecord, expected success, breakpoints, status>
```

`NodeCover(TA,T_i)` 只表示节点覆盖；`TraceEquivalent(TA,T_i)` 还要求关系和行为保持。融合可行性采用以下工程条件：

```text
FusionFeasible = SourceClosed
  ∧ NodeSemanticPreserved ∧ InterfaceContinuous ∧ BehaviorContinuous
  ∧ ConstraintsJointlySatisfiable ∧ CausalClosed(S/B→E)
```

该条件是技术事实分析，不是新的法定创造性要件。

```
主干链（D1）：  R₁ → F₁ → S₁ → S₂ → B₁ → B₂ → E₁
嫁接节点（D2）：                        S₃' → B₃'
                                    ↓
融合链 C_fused： R₁ → F₁ → S₁ → S₂ → S₃' → B₃' → E₁'
```

### 2.2 融合成功的必要条件

追溯链融合成功必须同时满足以下三个层次的条件：

| 层次 | 条件 | 说明 |
|------|------|------|
| **结构层（S）** | 接口兼容 | 被嫁接的 S 节点与主干 S 节点在尺寸、形状、连接方式上可对接 |
| **行为层（B）** | 行为连贯 | 嫁接前后的行为序列不间断，不产生矛盾的运动/受力/时序 |
| **功能-效果层（F/E）** | 效果保持 | 融合后的整链仍能实现有意义的技术效果，而非效果抵消或空转 |

### 2.3 融合失败的六种模式

#### 模式一：节点同一性冲突（S 层）

**定义**：两篇对比文件指向同一个物理位置或功能角色，但赋予了互斥的结构属性。

**MBSE 判断标准**：∃ Sᵢ ∈ D1, Sⱼ' ∈ D2，二者占据同一功能槽位，但结构属性不可共存。

**机械示例**：

| D1 节点 | D2 节点 | 冲突描述 |
|---------|---------|---------|
| D1.S2：被驱动件为链条，具有啮合齿形 | D2.S3'：被驱动件为板件，具有平直摩擦侧面 | 同一被驱动对象不能同时具有啮合齿形和平直摩擦面——二者互斥 |

**论证模板**：
> D1 的 Sᵢ 要求被驱动对象具有 [属性 A]，而 D2 的 Sⱼ' 要求同一对象具有 [属性 B]。属性 A 与属性 B 在同一物理实体上不可兼得，因此 D1 与 D2 在 S 层存在节点同一性冲突，无法融合。

#### 模式二：接口断裂（S 层→B 层）

**定义**：D2 被嫁接的节点输出类型与 D1 主干节点的输入类型不匹配，导致行为链在接口处断裂。

**MBSE 判断标准**：D1.Bₖ 的输出状态 ≠ D2.Fₘ' 所需的输入条件。

**机械示例**：

| D1 行为终点 | D2 功能起点 | 断裂描述 |
|------------|-----------|---------|
| D1.B2：链节绕链轮做圆周啮合运动（输出周期性离散运动） | D2.F1'：对具有连续平直侧面的工件施加摩擦力（需要连续面接触） | 链节无法提供连续平直侧面作为摩擦接触面 |

**论证模板**：
> D1 的行为 Bₖ 输出 [状态 X]，而 D2 的功能 Fₘ' 要求输入 [条件 Y]。由于 [状态 X] 不能满足 [条件 Y]，D2 的节点无法嫁接到 D1 的行为链上——在接口处发生断裂。

#### 模式三：功能层互斥（F 层）

**定义**：两篇文件在同一功能槽位上提出了互斥的实现方式，二者不可共存。

**MBSE 判断标准**：∃ F 槽位，D1 和 D2 各自提供了对该 F 槽位的实现，但两种实现方式在物理上互斥。

**机械示例**：

| 功能槽位 | D1 实现 | D2 实现 | 互斥原因 |
|---------|--------|--------|---------|
| 驱动传动单元 | 齿轮啮合传动（齿形啮合，节距匹配） | 摩擦传动（面接触，不依赖节距） | 同一驱动接口不能同时使用啮合和摩擦两种物理机制 |

**论证模板**：
> 在功能槽位 F 上，D1 通过 [方式 A] 实现，D2 通过 [方式 B] 实现。方式 A 和方式 B 依赖互斥的物理机制（[具体说明]），因此二者不能在同一技术方案中同时存在，也不存在用 B 替换 A 的技术基础。

#### 模式四：行为时序冲突（B 层）

**定义**：D1 和 D2 的行为在时间维度上存在不可调和的矛盾。

**MBSE 判断标准**：D1 的 B 序列要求步骤顺序 P₁ → P₂ → P₃，而嫁接 D2 的节点后要求顺序 P₁ → P₂' → P₃，其中 P₂' 与 P₂ 无法共存或 P₂' 破坏了 P₃ 的前提条件。

**机械示例**：

| D1 行为序列 | D2 嫁接要求 | 时序冲突 |
|------------|-----------|---------|
| 链条连续行进 → 链节经过链轮 → 啮合传力 | 嫁接：链节需在接触区域短暂停留以建立摩擦接触 | 连续行进与短暂停留不可兼得 |

#### 模式五：效果抵消（E 层）

**定义**：融合后，D2 节点的引入导致 D1 原有技术效果被削弱或取消，融合链成为一个无意义或劣化的方案。

**MBSE 判断标准**：E_fused < E_D1（融合后效果不如 D1 原有方案）。

**机械示例**：
> D1 通过啮合实现精确传动（E1：传动精度高）。嫁接 D2 的摩擦驱动后，啮合关系被破坏，传动精度丧失。融合方案的效果（低精度摩擦传动）不如 D1 原有方案，本领域技术人员没有动机进行此种劣化组合。

#### 模式六：问题消解（R 层）

**定义**：D2 所要解决的技术问题（R_D2），在 D1 的技术方案中已经以不同方式被解决或根本不存在。D2 的教导在 D1 的语境中没有用武之地。

**MBSE 判断标准**：R_D2 在 D1 的体系中被 D1 自身结构消解，不存在引入 D2 方案的需求。

**论证模板**：
> D2 所要解决的问题是 [R_D2]。但在 D1 的技术方案中，由于 D1 的 [结构/机制]，该问题已经不存在（或被以不同方式规避）。因此，本领域技术人员在面对 D1 时，没有动机去寻求 D2 的教导——D2 的教导在 D1 的语境中是冗余的。

## 3. 融合链覆盖分析：即使可融合，是否覆盖权利要求？

即使假定追溯链可以融合（即审查员的组合逻辑在技术上是可行的），还需要判断融合后的追溯链 C_fused 是否覆盖了权利要求的追溯链 C_claim。

### 3.1 覆盖不足的四种类型

#### 覆盖缺口一：S 节点缺失

C_fused 缺少 C_claim 中的一个或多个 S 节点。

```
C_claim:  S₁ → S₂ → S₃ → S₄
C_fused:  S₁ → S₂ → S₄        ← S₃ 缺失
```

**判断标准**：C_fused 的 S 节点集合不能完全覆盖 C_claim 的 S 节点集合。

**注意**：审查员有时会将权利要求的某个 S 节点"解释"为已隐含在对比文件中。此时应严格回归原文——如果对比文件未明确公开该 S 节点的技术内容，且不能从对比文件原文中"直接且毫无疑义地确定"，则该 S 节点即构成覆盖缺口。

#### 覆盖缺口二：S 节点关系不同

C_fused 中 S 节点之间的连接/配合/位置关系与 C_claim 不同。

```
C_claim:  [S₁] —铰接— [S₂] —贴合— [S₃]
C_fused:  [S₁] —固定— [S₂] —啮合— [S₃]   ← 关系不同
```

**判断标准**：即使 S 节点名称对应，节点之间的结构关系（连接方式、位置关系、配合关系）不同，即不构成覆盖。

#### 覆盖缺口三：行为路径不同

C_fused 的行为序列与 C_claim 不同，导致技术手段的工作方式有实质性差异。

```
C_claim:  B₁（摩擦面贴合驱动）→ B₂（板单元沿弧线摆动）
C_fused:  B₁'（链轮啮合驱动）→ B₂'（链节沿弧线被牵引）
```

**判断标准**：即使最终运动结果相似，运动和力的传递路径不同，即不构成覆盖。

#### 覆盖缺口四：效果层面不同

C_fused 的技术效果与 C_claim 的技术效果不同，或者 C_fused 无法实现 C_claim 所声称的技术效果。

```
C_claim  E₁：传动单元不受节距约束，可沿任意曲率路径行进
C_fused  E₁'：链条沿弧形导轨行进（链节仍受节距约束）
```

**判断标准**：C_fused 不能实现 C_claim 中与区别特征直接关联的技术效果。

## 4. 审查意见答复策略的 MBSE 形式化

### 4.1 答复的三种基本策略

基于上述理论框架，创造性答复可以形式化为以下三种策略：

| 策略 | MBSE 表述 | 适用场景 |
|------|----------|---------|
| **策略 A：融合不成立** | Fuse(C_D1, …, C_Dn) = ∅（六种失败模式至少一种成立） | 审查员的组合路径存在技术障碍 |
| **策略 B：融合链不覆盖** | Cover(C_fused, C_claim) = False（四种覆盖缺口至少一种成立） | 即使审查员组合逻辑可行，组合结果与权利要求不同 |
| **策略 A+B：双重防线** | Fuse = ∅ ∧ Cover = False | 最稳妥：既论证不可融合，也论证融合后不覆盖 |

### 4.2 答复论证的 MBSE 逻辑链

一份完整的创造性答复，其 MBSE 层面的论证逻辑如下：

```
1. 陈述审查员的组合路径（引用审查意见原文）
   → 审查员主张：C_D1 + C_D2 → C_fused，且 C_fused ≈ C_claim

2. 分析融合可行性
   → 识别融合失败模式（模式一至六）
   → 结论：Fuse(C_D1, C_D2) 不成立

3. （可选）分析覆盖完整性
   → 即使假定融合成立，识别覆盖缺口（缺口一至四）
   → 结论：Cover(C_fused, C_claim) = False

4. 结论
   → 审查员的创造性驳回理由不成立
   → 修改后的权利要求具备创造性
```

### 4.3 从 MBSE 论证到法律文书的转换规则

| MBSE 论证要素 | 法律文书转换 |
|-------------|------------|
| S 节点缺失 | "对比文件 D2 未公开权利要求 1 中的……结构特征" |
| 节点同一性冲突 | "D1 的……与 D2 的……属于不同的结构类型，不能简单替换" |
| 接口断裂 | "D2 的……以……为前提，而 D1 的……不满足该前提，因此无法将 D2 的方案应用于 D1" |
| 行为时序冲突 | "D1 要求……运动方式，而嫁接 D2 后该运动方式被破坏" |
| 效果抵消 | "组合后将丧失 D1 原有的……技术效果，本领域技术人员没有动机进行此种劣化" |
| 问题消解 | "D2 所要解决的技术问题在 D1 中已不存在，本领域技术人员没有动机参考 D2" |
| S 节点关系不同 | "权利要求 1 中……与……之间为……关系，而对比文件组合后为……关系，二者不同" |

## 8. 示例：板链摩擦驱动案

### 8.1 模型建立

**C_claim（修改后权利要求 1）**：

```
R₁：如何在内凹圆弧路径上实现连续大单元传动？
  → F₁：沿曲线路径驱动板状传动单元
    → S₁：机架具有内圆弧轨道和外圆弧轨道
    → S₂：第一传动板 + 第二传动板，通过铰接轴连接
    → S₃：第一滚轮 + 第二滚轮，分别位于内外圆弧轨道内
    → S₄：皮带 + 主动轮 + 从动轮 + 压带轮
    → S₅：皮带外侧壁贴合传动板侧面
      → B₁：电机驱动主动轮 → 皮带运转 → 皮带外侧壁摩擦传动板侧面
      → B₂：传动板被推动 → 滚轮沿轨道滚动 → 板单元绕铰接轴适应曲线
        → E₁：传动单元不受节距约束，可沿任意曲率连续行进
```

**C_D1（审查员认定的最接近现有技术）**：

```
R₁'：如何沿曲线路径输送物品？
  → F₁'：沿曲线导轨驱动输送单元
    → S₁'：弧形导轨
    → S₂'：链条（多节链环通过销轴串联）
    → S₃'：链轮（与链条啮合）
      → B₁'：链轮旋转 → 啮合驱动链条 → 链条沿导轨行进
      → B₂'：链节绕弧形导轨逐个通过弯曲段
        → E₁'：链条可沿曲线输送物品
```

**C_D2（审查员引用提供摩擦驱动的对比文件）**：

```
R₂'：如何无啮合地驱动工件？
  → F₂'：以面接触摩擦力驱动工件
    → S₄'：传送带（平皮带）
    → S₅'：皮带表面接触工件侧面
      → B₃'：传送带运转 → 摩擦力作用于工件侧面 → 工件被推动行进
        → E₂'：避免啮合结构，简化驱动
```

### 8.2 审查员的组合主张

> 审查员认为：D1 公开了曲线输送结构（S₁'→S₃'），D2 公开了摩擦驱动方式（S₄'→S₅'）。将 D2 的摩擦驱动替换 D1 的链轮啮合驱动是显而易见的。

翻译为 MBSE：
> 审查员主张：Fuse(C_D1, C_D2) = 取 D1 的 R₁'→F₁'→S₁'→S₂'→B₂'→E₁'，将 D1.B₁'（链轮啮合驱动）替换为 D2 的 S₄'→S₅'→B₃'。

### 8.3 融合分析

**尝试融合**：

```
拟融合链：
  R₁'→F₁'→S₁'（弧形导轨）→S₂'（链条）→ [嫁接] S₄'（皮带）→S₅'（皮带贴侧面）→B₃'（摩擦驱动）→B₂'（沿导轨行进）→E₁'
```

**融合失败分析**：

| 失败模式 | 判断 | 依据 |
|---------|------|------|
| **模式一：节点同一性冲突** | ❌ 成立 | D1.S₂'（链条）要求被驱动件具有与链轮啮合的齿形结构；D2 的摩擦驱动要求被驱动件具有平直的可接触侧面。链条的链节不具备平直侧面，且改变链节外形将破坏其与链轮的啮合关系。 |
| **模式二：接口断裂** | ❌ 成立 | D1.B₁' 原有的啮合驱动力被移除后，B₂'（链节沿导轨行进）的驱动力来源消失——摩擦驱动无法有效驱动链条中的每个链节，因为非直接接触摩擦面的链节仅能通过相邻链节的牵引力运动，而短节距链节在弧线段的内外侧速度差会导致卡滞。 |
| **模式三：功能层互斥** | ❌ 成立 | 驱动功能槽位：啮合传动与摩擦传动在物理机制上互斥——前者依赖节距匹配和齿形啮合，后者依赖面接触摩擦，同一驱动接口不能同时实施两种机制。 |
| **模式六：问题消解** | ⚠️ 可选 | D2 解决的是"如何无啮合驱动独立工件"的问题。但 D1 的链条体系本身就依赖啮合传动，不存在"避免啮合"的需求。本领域技术人员没有动机在链条体系中引入摩擦驱动来解决一个不存在的问题。 |

**结论**：Fuse(C_D1, C_D2) 不成立。审查员的组合路径在模式一、二、三上存在不可逾越的技术障碍。

### 8.4 覆盖分析（即使假设融合成立）

即使假定可以强行嫁接，C_fused 与 C_claim 之间仍然存在覆盖缺口：

| 覆盖缺口 | C_claim | C_fused（假定） | 差异 |
|---------|---------|---------------|------|
| S 节点缺失 | S₂：第一传动板 + 第二传动板，铰接连接 | D1.S₂'：链条（多节链环，销轴串联） | 板状传动单元 ≠ 链条链环。板可做大，链节受节距约束 |
| S 节点关系不同 | S₅：皮带外侧壁**贴合**传动板侧面 | S₅'：皮带表面**接触**工件侧面 | "贴合"≠"接触"。贴合暗示持续面接触和适配关系 |
| 行为路径不同 | B₂：滚轮沿内外轨道滚动 → 板单元绕铰接轴适应曲线 | B₂'：链节逐个进入弧形导轨 → 链节间相对转动 | 板单元的滚轮-轨道导向 ≠ 链节的导轨约束 |
| 效果不同 | E₁：传动单元不受节距约束，可沿任意曲率行进 | E₁'：链条沿现有弧形导轨行进（仍受节距约束） | C_fused 不能实现"不受节距约束"的效果 |

**结论**：即使融合成立，Cover(C_fused, C_claim) = False。

### 8.5 转化为答复论证

> **关于区别技术特征一（板链结构）**：D1 公开的是传统链条结构，链节受节距约束，无法做大。本申请修改后的权利要求 1 限定了由第一传动板、第二传动板通过铰接轴连接形成的板状传动单元，该结构提供了形成可做大传动单元的结构基础，不受链条节距的约束。D1 和 D2 均未公开该板链结构，也未给出将链条改造为板状传动单元的技术启示——因为链条的工作方式依赖节距匹配和链轮啮合，改变链节为板状将直接破坏其与链轮的啮合关系（融合失败模式一）。
>
> **关于区别技术特征二（摩擦驱动单元与传动板的贴合关系）**：即使将 D2 的摩擦驱动方式引入 D1，皮带外侧壁贴合的是链条链节的侧面，但链节侧面并非设计为摩擦驱动面，且非直接接触皮带的链节仍需通过相邻链节牵引传力，在弧形段将导致内外侧速度差无法补偿。本申请中皮带外侧壁与传动板侧面形成持续面贴合，传动板直接接受摩擦力而非通过邻接单元牵引——二者在受力路径上存在实质性区别（融合失败模式二；覆盖缺口三）。

## 9. 生化域示例：药物组合物案

### 9.1 模型建立

**C_claim（修改后权利要求 1）**：

```
R₁：如何提高药物 A 的口服生物利用度而不增加胃肠道副作用？
  → F₁：促进药物 A 的肠道吸收
    → S₁：药物 A（活性成分），含量 10-50 mg
    → S₂：吸收促进剂 B（中链脂肪酸甘油酯），含量 50-200 mg
    → S₃：pH 调节剂 C，使组合物在肠道 pH 下释放
    → S₄：药物 A 与吸收促进剂 B 的重量比为 1:2 至 1:10
      → B₁：口服后，pH 调节剂 C 在胃酸中保持组合物稳定
      → B₂：进入肠道后，pH 调节剂 C 溶解，释放药物 A 与吸收促进剂 B
      → B₃：吸收促进剂 B 通过 [机制] 促进药物 A 的肠道吸收
        → E₁：药物 A 的口服生物利用度提高至 XX%，且胃肠道副作用不增加
```

**C_D1（审查员认定的最接近现有技术）**：

```
R₁'：如何提高药物 A 的口服吸收？
  → F₁'：提高药物 A 的溶出度
    → S₁'：药物 A，含量 10-100 mg
    → S₂'：崩解剂（交联聚维酮）
    → S₃'：肠溶包衣
      → B₁'：肠溶包衣在胃中不溶解 → 进入肠道后溶解 → 药物 A 与崩解剂释放
        → E₁'：药物 A 在肠道中快速崩解，提高溶出度
```

**C_D2（审查员引用提供吸收促进剂的对比文件）**：

```
R₂'：如何提高亲脂性药物的口服吸收？
  → F₂'：通过淋巴转运途径提高药物吸收
    → S₄'：脂质载体（长链脂肪酸甘油酯）
    → S₅'：表面活性剂
      → B₂'：脂质载体在肠道中形成胶束 → 包裹药物 → 经淋巴系统吸收
        → E₂'：提高亲脂性药物的口服生物利用度
```

### 9.2 审查员的组合主张

> 审查员认为：D1 公开了药物 A 的肠溶制剂，D2 公开了以脂质载体促进亲脂性药物吸收的技术方案。将 D2 的吸收促进剂替换 D1 的崩解剂是显而易见的，因为二者都属于提高口服吸收的常规手段。

### 9.3 融合分析

**融合失败分析**：

| 失败模式 | 判断 | 依据 |
|---------|------|------|
| **模式一：节点同一性冲突** | ❌ 成立 | D2.S₄'（长链脂肪酸甘油酯）与本申请 S₂（中链脂肪酸甘油酯）看似同属脂质载体，但 D2 依赖长链脂肪酸形成胶束并经淋巴转运，而本申请使用中链脂肪酸并经门静脉途径吸收。二者在吸收机制上不同——长链脂肪酸形成的胶束结构与中链脂肪酸不同，不能简单替换。 |
| **模式二：接口断裂** | ❌ 成立 | D2 的脂质载体需要与表面活性剂(S₅')配合形成胶束。D1 的制剂中不包含表面活性剂，将 D2 的脂质载体引入 D1 后，缺乏形成胶束的必要条件，脂质载体无法发挥其促进吸收的功能。 |
| **模式三：功能层互斥** | ⚠️ | 给药途径槽位：D2 通过淋巴转运，本申请通过门静脉途径——两种吸收途径的机制不同，对载体结构的要求不同。 |
| **模式五：效果抵消** | ❌ 成立 | D2 的长链脂肪酸甘油酯可能增加胃肠道负担，与本申请"不增加胃肠道副作用"的 R 节点目标矛盾。组合后可能提高了吸收但增加了副作用，违背了本申请的整体技术目标。 |

**结论**：Fuse(C_D1, C_D2) 不成立。

### 9.4 覆盖分析

| 覆盖缺口 | C_claim | C_fused（假定） | 差异 |
|---------|---------|---------------|------|
| S 节点缺失 | S₂：中链脂肪酸甘油酯（特定碳链长度） | D2.S₄'：长链脂肪酸甘油酯 | 碳链长度不同，吸收机制不同 |
| S 节点缺失 | S₃：pH 调节剂 C | D1 和 D2 均未公开 | 缺失 |
| S 节点关系不同 | S₄：药物 A 与吸收促进剂 B 重量比 1:2 至 1:10 | D1 和 D2 未公开该比例关系 | 特定比例带来的协同效果缺失 |

### 9.5 转化为答复论证

> **关于区别技术特征一（中链脂肪酸甘油酯作为吸收促进剂）**：D2 公开的是长链脂肪酸甘油酯通过淋巴转运促进药物吸收，而本申请选择中链脂肪酸甘油酯通过门静脉途径促进吸收。两种脂肪酸甘油酯的碳链长度、吸收机制和代谢途径均不同，本领域技术人员在 D2 的教导下不会自然想到以中链替代长链——因为长链脂肪酸的淋巴转运效果与其碳链长度直接相关，缩短碳链会导致淋巴转运效率显著降低（融合失败模式一、三）。
>
> **关于区别技术特征二（特定的重量比范围）**：本申请限定的药物 A 与吸收促进剂 B 的重量比 1:2 至 1:10 并非任意选择。在该比例范围内，吸收促进剂 B 既能有效促进药物 A 的吸收，又避免了过量脂质引起的胃肠道副作用。D1 和 D2 均未公开或教导该比例关系，本领域技术人员没有动机通过常规实验得到该特定范围（覆盖缺口三）。

## 10. 电子通信域示例：信道估计与信号检测案

### 10.1 模型建立

**C_claim（修改后权利要求 1）**：

```
R₁：如何在大规模 MIMO 系统中以低复杂度实现高精度信道估计？
  → F₁：基于压缩感知的信道估计
    → S₁：基站端配置 M 根天线（M ≥ 64）
    → S₂：导频分配模块，将导频序列分为 G 组
    → S₃：信道估计模块，对每组导频独立执行 OMP 算法
    → S₄：信道重建模块，将各组估计结果合并为完整信道矩阵
    → S₅：各组导频的分配基于用户的空间角度域稀疏性
      → B₁：导频分配模块根据用户角度域特征将用户分为 G 组
      → B₂：每组内的用户使用正交导频，组间导频可复用
      → B₃：信道估计模块对每组独立执行 OMP 算法，估计该组的信道向量
      → B₄：信道重建模块按角度域分组信息合并各组估计结果
        → E₁：计算复杂度从 O(M³) 降至 O(G·(M/G)³)，同时保持估计精度
```

**C_D1（审查员认定的最接近现有技术）**：

```
R₁'：如何在大规模 MIMO 中降低信道估计的导频开销？
  → F₁'：基于空间稀疏性的导频复用
    → S₁'：基站端配置 M 根天线
    → S₂'：导频分配单元，根据用户空间特征分配导频
      → B₁'：将空间角度域可分离的用户分配不同导频组
      → B₂'：组内用户使用正交导频
        → E₁'：减少所需导频数量
```

**C_D2（审查员引用提供 OMP 算法的对比文件）**：

```
R₂'：如何在压缩感知框架下高效重建稀疏信号？
  → F₂'：以低复杂度重建稀疏信号
    → S₃'：OMP（正交匹配追踪）算法模块
      → B₃'：接收观测向量和感知矩阵 → 迭代选择最匹配原子 → 更新残差 → 输出稀疏信号估计
        → E₂'：以 O(K·M·N) 的复杂度重建 K-稀疏信号
```

### 10.2 审查员的组合主张

> 审查员认为：D1 公开了大规模 MIMO 中基于空间稀疏性的导频分配方案，D2 公开了 OMP 压缩感知重建算法。将 D2 的 OMP 算法应用于 D1 的导频分配系统以进行信道估计是显而易见的——因为 OMP 是压缩感知领域的常规算法。

### 10.3 融合分析

**融合失败分析**：

| 失败模式 | 判断 | 依据 |
|---------|------|------|
| **模式一：节点同一性冲突** | ⚠️ | D2 的 OMP 算法是通用的稀疏信号重建算法，可以应用于不同场景。但 D2 没有公开如何将 OMP 与 D1 的特定导频分组方案结合——即如何利用 D1 的"角度域分组信息"来构建 OMP 的感知矩阵。 |
| **模式二：接口断裂** | ❌ 成立 | D1 输出的是"空间角度域分组后的导频分配方案"，但 D2 的 OMP 算法需要"观测向量"和"感知矩阵"作为输入。D1 和 D2 均未公开如何从 D1 的分组结果生成 D2 所需的感知矩阵。具体来说，感知矩阵的构建依赖于用户信道的角度域稀疏特征——如何将 D1 的分组信息转化为感知矩阵的结构，是本领域技术人员需要解决的一个中间技术问题。 |
| **模式六：问题消解** | ⚠️ | D2 解决的是"通用稀疏信号重建的复杂度问题"。但在 D1 的大规模 MIMO 场景中，直接将通用 OMP 应用于全体天线（M ≥ 64）会导致感知矩阵维度爆炸，反而增加复杂度。本申请通过 S₅（角度域分组）对 OMP 进行分组执行，才解决了规模适配问题。D1+D2（不加分组）的组合在缩放至大规模天线时并不成立。 |

### 10.4 覆盖分析

| 覆盖缺口 | C_claim | C_fused（假定） | 差异 |
|---------|---------|---------------|------|
| S 节点缺失 | S₅：各组导频的分配基于用户的空间角度域稀疏性 | D1+D2 未公开 | 缺失——这是分组 OMP 与通用 OMP 的关键区别 |
| S 节点缺失 | S₄：信道重建模块，将各组估计结果合并 | D1+D2 未公开 | 缺失——分组估计后的合并步骤未被教导 |
| 行为路径不同 | B₃→B₄：分组独立估计→合并 | D₂ 的 B₃'：整体一次性估计 | 分组执行与整体执行在计算结构和中间结果处理上不同 |

### 10.5 转化为答复论证

> **关于区别技术特征一（基于角度域稀疏性的分组 OMP 信道估计）**：D2 公开的是通用的 OMP 压缩感知重建算法，但并未教导如何将该算法适配至大规模 MIMO 系统的信道估计场景。本申请的核心创新在于 S₅——基于用户空间角度域稀疏性对导频和 OMP 进行分组。正是这一分组策略，使得 OMP 的感知矩阵维度从 M 降至 M/G，从而在实际的大规模天线场景中实现可行的复杂度降低。D1 和 D2 均未公开该分组策略，也未给出将角度域信息用于构建分组感知矩阵的技术启示（融合失败模式二；覆盖缺口一）。
>
> **关于区别技术特征二（分组估计后的信道重建）**：即使将 D2 的 OMP 应用于 D1，各组独立估计后得到的是一组不完整的信道估计值。本申请 S₄ 限定的信道重建模块负责将各组结果按角度域分组信息合并为完整信道矩阵——这一合并步骤对于获得可用的信道估计是必不可少的。D1 和 D2 均未公开该重建步骤（覆盖缺口二）。
