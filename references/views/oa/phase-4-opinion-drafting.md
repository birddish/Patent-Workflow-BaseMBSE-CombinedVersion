# 阶段四：撰写审查意见答复

## 目的

基于前三阶段的 MBSE 模型（阶段一）、事实审计报告（阶段二）和追溯链分析报告（阶段三），撰写审查意见答复或复审意见陈述书。

## 核心原则

1. **证据锚定和原文直接呈现原则**：每个论证点必须有阶段二或阶段三的证据支撑，并在正文中直接呈现足以理解当前论点的 OA/决定原文、修改后权利要求原文、对比文件原文或申请文件支持原文。阶段二核实结论编号（如 F-01）和阶段三断裂点编号（如 C-01-B1）只能作为定位辅助，不能替代原文。
2. **不引入新事实原则**：答复中不得出现前三阶段未建立的、未经核实的事实主张或技术断言。
3. **逐点回应原则**：审查意见中提出的每一个问题都必须得到回应，不得遗漏；正文标题应直接写明审查员指出的具体问题，不使用没有信息量的“问题一”“问题二”作为唯一标题。
4. **审查员链条回放优先原则**：先复述 D0、Dk、各文件技术作用、组合或修改操作和中间状态，再沿断点转换为申请人意见或补正；技术路线分析用于解释断点，不得跳过审查员路径。
5. **意见/补正分流原则**：`ArgumentOnly` 不改变权利要求版本；`AmendmentBased` 必须建立新版本、重建 `TA` 并使旧 NB/IS/ResponseTrace 失效。

## 原文直接呈现的强制规则

### 不允许的最小引用

以下写法不能作为完整事实依据：

```text
见 D1 第 0034 段。
见说明书第 12 页。
见权利要求 1。
详见前述证据。
```

### 必须采用的内容单元

每个实质问题至少包含：

1. 审查意见或驳回决定相关原文；
2. 被引用的对比文件或申请文件相关原文；
3. 修改后的被评价权利要求完整文本或足以保留全部限制的连续摘录；`ArgumentOnly` 未发生修改时，仅呈现当前问题所必需的相关权利要求原文；
4. 本申请文本如何记载、对比文件如何记载，以及二者之间的对应、缺失、冲突或范围关系；
5. 审查员认知错误的具体内容；
6. 申请人的事实回应、技术分析和处理动作；
7. 原文定位和内部追溯编号，放在直接内容之后。

原文无法取得时，应直接写明“原文未提供/待核验”，将事项保持 `Q`，不得以 `path`、`location`、`source_ref`、文件名或段落编号补足内容。直接内容规则见 `references/oa-direct-content-rules.md`；具体模板按 `references/templates/template-registry.md` 选择。

## 前置输入确认

在开始撰写前，确认以下输入齐全：

- [ ] 阶段一：申请文件 MBSE 模型、各对比文件 MBSE 模型、节点对照总表
- [ ] 阶段二：审查意见事实主张核实表、事实核实审计报告
- [ ] 阶段三：审查员组合路径追溯链映射、结合可行性分析表、追溯链分析报告
- [ ] 最新的修改后权利要求文本；`ArgumentOnly` 未修改时，确认当前问题所需的相关权利要求原文
- [ ] 用户指定的术语、特征顺序和论证优先级（如有）
- [ ] 问题—处理动作矩阵已建立，审查意见问题总数与矩阵行数一致
- [ ] 当前权利要求有唯一版本 ID，且所有修改事件、支持依据和 `supersedes` 关系已回写
- [ ] 唯一活动权利要求集合、唯一活动快照和唯一主修改策略已冻结
- [ ] 修改影响闭包内全部权利要求及引用路径均完成NB/IS结构化记录，旧NB/IS/RT已失效
- [ ] `recalculation_gate.passed=true`；否则只允许输出内部条件性草稿
- [ ] 新版权利要求的必要特征、区别特征、实际技术问题和组合路径已重算
- [ ] 每条 `CombinationPath` 均能按中间状态回放，并有正向闭合与反向断裂记录
- [ ] 每项技术效果均关联 `EffectEvidenceCard`，载明比较基准、来源日期和权利要求范围覆盖

## 案件类型判断与模板选择

阶段四不再在本文件中重复完整的对外正文模板。先读取 `templates/template-registry.md`，再根据案件入口和答复模式选择唯一主模板：

| 案件入口/交付物 | 正式模板 | 选择条件 |
|---|---|---|
| 审查意见答复 | `templates/external/oa-response.md` | 输入为第几次审查意见通知书 |
| 驳回复审意见陈述书 | `templates/external/reexamination-statement.md` | 输入为驳回决定或复审材料 |
| 权利要求修改说明 | `templates/external/amendment-explanation.md` | 需要单独说明 `AmendmentBased` 修改 |
| 内部问题—动作矩阵 | `templates/internal/intake-and-issue-matrix.md` | 尚未形成对外正文 |
| 内部直接内容证据表 | `templates/internal/evidence-direct-content-sheet.md` | 需要整理原文和事实核对 |
| 内部版本与重算登记 | `templates/internal/claim-version-recalculation-sheet.md` | 发生权利要求修改或版本替代 |

### 对外问题单元的统一骨架

无论使用 OA 答复模板还是复审模板，每个具体问题都必须按照下列顺序组织，具体正文以所选模板为准：

```text
存在的问题
→ 审查意见/决定原文
→ 本申请文本如何记载
→ 对比文件如何记载
→ 审查员认知错误的具体内容
→ 申请人回应或修改动作
→ 处理结果和待核验事项
```

### 模式分流

- `ArgumentOnly`：不建立新权利要求版本；外部模板中不虚构修改后文本，只保留具体问题所需的相关权利要求原文；
- `AmendmentBased`：先读取内部版本与重算模板，完成支持依据、活动快照、影响闭包和重算门，再使用外部模板；
- 材料不足：只使用内部模板形成条件性稿，不直接套用外部模板生成可提交答复。

## 论证撰写指南

### 审查员链条回放

每个创造性争点先按以下顺序形成内部记录：

```text
审查员断言 → 引证段落 → 权利要求特征 → 区别与效果
→ 组合/修改操作 → 接口、行为或因果断点 → 申请人行动 → 结果理由
```

回放时必须说明 D0、Dk 及其各自承担的技术作用；不得以“分别存在特征”代替路径证明，也不得从“工程上可以设计”直接推出“现有技术能够到达”。Could-Would 仅作为下游规范接口检查。

### 先确定处理动作

撰写前，为每个 `office_action_issue` 选择唯一主处理动作：

| 条件 | 主处理动作 | 输出要求 |
|---|---|---|
| 事实认定正确，无需改变范围 | 认可 | 简要确认，不制造伪争议 |
| 事实或技术启示缺少证据 | 争辩 | 给出原文位置、偏差与追溯断点 |
| 表达可改进且范围代价可接受 | 修改 | 列出修改前后、支持依据和范围影响 |
| 从属特征或方案价值低于程序成本 | 删除 | 说明删除对引用关系与保护范围的影响 |
| 单一性/保护策略需拆分 | 分案 | 标记需客户确认的对象和期限 |
| 事实、日期或客户意图不足 | 补充核验/客户确认 | 标记 `Q`，不得宣称已可提交 |

主处理动作之外可记录辅助动作，但不得出现同一问题在不同文件中被同时标记为“认可”和“否认”。

### 权利要求版本重计算门

对每个新 `CLM` 版本，依次重新确定：

`CLM 文本 → 必要 CF/REL → 区别特征 → 技术效果边界 → 实际技术问题 → NB/IS → 答复论证`。

任一环节仍引用旧 `CLM` 的区别特征、问题或结论时，回退到阶段一/三重新计算。

### 事实陈述


使用阶段二中核实为 `✅ 支持` 或 `⚠️ 部分支持` 的事实时，先直接粘贴审查意见和对比文件的相关原文，再作事实归纳。来源定位只能跟在原文之后：

> 审查意见原文：“【直接粘贴相关完整句子或连续段落】”

> D1 原文：“【直接粘贴相关完整句子或连续段落】”

来源定位：【审查意见页码/段落；D1 段落或页码】。定位仅用于复核，不替代上述原文。

基于上述原文，可以审慎表述为：【仅归纳原文明确支持的内容】。不得先写“D1 公开了……”再只给一个事实核实编号。

### 反驳论述


使用阶段二中核实为 `❌ 不支持` 或 `🚫 无记载` 的事项时，必须先分别直接呈现审查意见和对比文件原文：

> 审查意见原文：“【直接粘贴审查员的完整认定】”

> D1 原文：“【直接粘贴与该认定对应的完整句子或连续段落】”

来源定位：【审查意见和 D1 的具体位置】。定位仅用于复核，不替代上述原文。

上述原文表明：【说明审查员认定与对比文件实际记载的对应、遗漏或冲突】。如对比文件原文未提供，应直接写“原文未提供/待核验”，不得以 `F-02`、路径或文件名补足事实。

### 技术启示反驳

使用阶段三的追溯链分析：

> 审查员主张将 D2 的摩擦驱动方式应用于 D1 的链条结构（组合 C-01）。但从追溯链分析可见（见追溯链分析报告 §2.1），D1 的追溯链在 B1 节点（链轮啮合驱动链条沿导轨行进）处发生断裂——若改为摩擦驱动，D1 不再具有啮合驱动力，其原有的"链轮啮合驱动"这一行为无法执行。同时，D1 与 D2 在驱动界面和接口维度存在不兼容（见结合可行性分析表 C-01），二者不具备结合的技术基础。

上述段落必须先完整重放 `CombinationPath`，再分别指出来源、节点语义、接口、行为、约束和 `S/B→E` 因果是否闭合；融合不可行只是技术事实依据，最终仍需完成区别效果、实际技术问题、技术启示和合理成功预期的法律转换。

### 意见书与补正分流

- **`ArgumentOnly`**：权利要求文本和 `ClaimVersion` 不变；答复仅处理事实认定、区别特征、效果、结合动机、阻碍因素或路径断点。
- **`AmendmentBased`**：记录修改前后版本、支持依据和范围影响，重建 `TA(C')`、NB、`CombinationPath`、`Δ*` 与效果卡；旧答复和旧效果判断标记 `superseded/invalidated`，通过 `recalculation_gate` 后才可形成对外稿。
- 对外稿不出现 `OAIssue`、`CombinationPath`、`EffectEvidenceCard` 等内部名称，但内部 `ResponseEvent` 和 `DecisionTrail` 必须保留完整链接。

### 不兼容论证

根据当前 mode 选用对应的域论证模式文件：

- **mechanical** → `references/domain-argument-patterns-mechanical.md`，先按 ME-01 至 ME-06 选择具体断点；ME-01/ME-06 处理整体结构与结构需求因果，ME-02/ME-03/ME-04 处理组合路径，ME-05 处理传统替代方案。
- **biochemical** → `references/domain-argument-patterns-biochemical.md`，先按 BC-01 至 BC-06 选择具体断点；BC-01/BC-02 处理相容性和工艺条件，BC-03/BC-06 处理范围与具体选择，BC-04 处理反向教导，BC-05 处理效果和整体协同。
- **electronic-communication** → `references/domain-argument-patterns-electronic-communication.md`，先按 EC-01 至 EC-06 选择具体断点；EC-01/EC-04 分别处理跨模块输入适配与内部中间状态，EC-02 处理协议/架构/同步，EC-03 处理算法—硬件/资源/实时性，EC-05 处理问题—约束—教导方向，EC-06 仅处理技术性与算法—技术对象耦合边界。

**通用论证模板**：

> 对比文件 D1 的 [方案/体系] 以 [前提条件 A] 为基础，而对比文件 D2 的 [教导/方案] 以 [前提条件 B] 为前提。先重放 CombinationPath：D0=[文件及证据]，Dk=[文件及证据]，操作=[加入/替换/重连/重排]，中间状态=[逐步变化]。再说明 [来源/节点语义/接口/行为/约束/S/B→E] 中的具体断点及其证据状态。该断点说明组合路径尚未被充分证明；是否构成结合动机不足、阻碍因素或效果不可合理预期，仍须完成下游法律评价。

### 整体协同效果

机械案件应先完成域模式文件中的 MechanicalCooperationCheck；biochemical 案件应先完成 ChemicalClosureCheck。二者都必须说明特征之间的结构、接口、受力、运动、组成、工艺、状态或效果联系，并使用比较基准和范围覆盖。不能因为存在多组区别特征就当然主张协同。

> 上述区别技术特征并非彼此孤立的零件、组分或步骤，而是通过……结构/接口/受力/组成/工艺/状态关系共同构成……技术手段。各组特征在【具体工况】下相互支持，共同影响【客观指标】；删去或替换任一组后，【中间状态/约束/因果链】不再闭合。该结论以 EffectEvidenceCard 的比较基准和支持位置为限。
## 从属权利要求处理

- 从属权利要求必须先沿每条合法引用路径展开完整评价对象；不得只评价其新增限定；
- 即使OA未单独攻击，也必须建立 `inherited` 或 `no_separate_issue` 的NB/IS记录，明确继承路径、附加限定和为什么无需单独争议；
- OA单独攻击的从属权利要求使用 `full` 记录并在对外答复中作对应论证；
- 不得将已纳入修改后独立权利要求的特征重复作为从属权利要求的贡献。

## 阶段四完成确认

- [ ] 所有阶段一至三的输出已作为论证依据引用；
- [ ] 每个论证点可追溯到具体的核实结论编号或断裂点编号；
- [ ] 未引入前三阶段未建立的新事实；
- [ ] 审查意见中每个问题均已回应；
- [ ] 格式符合对应案件类型的模板结构。
- [ ] 每个问题 ID 在答复中有唯一主处理动作与明确位置；
- [ ] 每个实质论证点已回写 `response_trace`；
- [ ] 对外答复稿不含 `F-01`、`C-01`、`R1/F1/S1/B1/E1`、`D/I/Q/X` 等内部编号或状态标签。
- [ ] 对外答复开头只写明本次审查意见/决定及发文日，缺失日期已明确标记待核验；
- [ ] 对外答复不设置独立的当前权利要求总览；`ArgumentOnly` 的相关权利要求原文位于对应问题下，`AmendmentBased` 的修改后权利要求位于对应问题下；
- [ ] 每个实质性事实或法律论点均有直接原文或“原文未提供/待核验”，不存在 `citation-only` 段落；

**仅在上述全部确认后，进入阶段五。**

## 补充：模式分流和 AI 候选文本

`ArgumentOnly` 只针对当前 `ClaimVersion` 争辩事实、区别、效果或技术启示；`AmendmentBased` 必须先记录 `AmendmentEvent`、原始支持和影响闭包，再生成新权利要求版本并重新计算受影响的 `TA/NB/IS`；`Interview` 只记录沟通事件；`Appeal` 以驳回决定和复审评价对象为入口。四种模式的结果不得互相冒充。

AI 可以提供候选答复段落、引用段落和补正文本，但没有原文支持或未完成重算门时只能作为内部条件性草稿。最终答复不得显示内部 ID、状态标签或模型评分，也不得把官方演示、预印本、数据集或相似度结果写成中国法下的实体结论。

### 内部工作稿与对外答复稿的双轨交付

内部工作稿用于审计和回放，必须保留 `OAIssue`、`CombinationPath`、`EffectEvidenceCard`、`ResponseEvent`、`AmendmentEvent`、`ClaimVersion`、`AnalysisSnapshot`、`DecisionTrail`、`SupportLink`、`Q` 和 `freeze_revision`。对外答复稿仅保留完整的事实、技术和法律语言，不出现上述对象名称、内部ID、`R/F/S/B/E` 节点符号、`D/I/Q/X` 状态、数据集任务标签或自动评分。对外稿生成前，阶段五必须确认正向与反向答审链均已闭合；否则只交付条件性内部稿。

创造性方法层统一采用“最接近现有技术—区别特征—技术效果—实际技术问题—组合动机/技术启示—接口/行为/约束断点—合理成功预期—申请人行动”顺序。法域字段只作为来源元数据，不阻断方法层回归，也不替代适用法下的实体审查。
