模板 ID：`EXT-INVALID-02`
文件：`external/invalidation-defense.md`
适用入口：无效宣告程序中的专利权人答辩（第一次答辩及第二次及后续补充答辩）
适用内部视图：`无效视图`
适用合同：`v2.1-invalidity`
参考来源：

- 本运行时模板改编自研发参考模板；运行时不得读取原始 DOCX，仅使用主 JSON。                                               
                                                                                                                                                                                                                                                                               

本模板只规定对外正文的章节骨架与必备要素。请求人主张的事实核对、证据原文摘录、特征—证据追溯链和权利要求版本重算在内部流程中完成；本模板不替代证据核实，也不产生法律结论。

## 一、使用规则

- 首部只写明本次答辩针对的无效宣告请求书、请求人提出请求之日、案件编号和发文日，不展开无关案件背景；本次答辩使用了公知常识证据的，在首部后单独声明该证据的名称、来源、版次、公开时间及其公开性说明；
- 第二次及后续答辩，对请求人新增的证据或补充理由必须逐项完整回应；对已充分陈述且请求人未提出新理由的事项，可写明"参见专利权人【日期】提交的意见陈述书第【】节，在此不再赘述"，但不得省略对新增主张的回应；
- 各节按请求人主张的理由顺序编排（常见顺序：26.4 得到说明书支持 → 22.2 新颖性 → 22.3 创造性 → 33 修改超范围 → 实施细则 23.2 必要技术特征 → 证据资格），节标题应写明实际核验的权利要求范围、理由类别和逐项结论；不得预设全部权利要求均成立，也不得只写“理由一”“理由二”；
- 新颖性采用单独对比原则，每一权利要求只与一份对比文件单独比对，不得以证据组合评述新颖性；只有创造性才允许证据组合；
- 特征拆解：独立权利要求的 `N.1` 固定为**主题名称（标题）**，`N.2` 起才是前序部分和技术特征部分的技术特征；从属权利要求的 `N.1` 即第一个附加技术特征，不设主题名称行；
- 全文特征编号体例必须统一（`N.1`、`N.2`…… 或 `N-1`、`N-2`……择一，不得混用），并与请求人的编号可追溯对应；
- 对照表的"答辩意见"列不得留空，已公开的也要写明"证据1公开了……"；未公开的写明"证据1未公开特征N.x：根据证据1【00XX】段描述'……'……因此，证据1未公开特征N.x"；
- 26.4 答辩按"《专利审查指南》第二部分第二章3.2.1 的依据 → 权利要求原文 → 说明书原文 → 本领域技术人员可合理预测等同替代或明显变型 → 结论"五步逐技术特征展开；
- 22.3 答辩对请求人举证的每一份证据逐一反驳，写明"证据X也未公开上述区别技术特征……；在证据X中说明书【00XX】段公开'……'。因此证据X明显不具有……特征。此外，证据X从整体技术方案来看与本专利或者证据1差异巨大，基于目前已核实的接口、输入输出和行为材料，尚不能确认能够结合，目前尚未核实到足以支持该组合路径的明确启示，仍需结合整体技术方案和证据进一步核对"；
- 引用请求人主张、本专利文本和证据时直接粘贴原文并标注权利要求号、说明书段号或附图号；只有段号、页码、附图号或文件编号而没有直接原文的段落属于 `citation-only` 违规；
- 主张"非惯用技术手段"或"克服技术偏见"时，必须给出本领域通常做法的依据或现有技术偏见的具体内容，并写明请求人未就此举证；
- 从属权利要求必须写明引用关系（"是对权利要求【N】的进一步限定"），并写明“在权利要求【N】的逐项核验结论基础上”；
- 请求人未主张的无效理由不写入正文；已主张的抗辩点不得放弃；
- 全文不得出现内部对象名、状态标签、数据集 ID、任务 ID 或检索中间结果编号；
- 原文、日期、段号或译文缺失时，保持"原文未提供／待核验"，不生成确定性结论；
- 模板不自动生成 DOCX、PDF 或其他非文本文件，除非用户另行明确指定格式和操作。

## 五、模式限制

- 抗辩点的取舍、证据组合的反驳顺序和公知常识链的反驳由无效视图内部完成，本模板不替代该分析；
- 对照表中的"未公开"结论必须逐项可追溯到证据原文，未核验的一律写"待核验"；
- 请求人未主张的理由不写入正文，模板不自行增加或放弃抗辩点；
- 是否修改权利要求（删除、合并、进一步限定）以用户确认为准，模板不自行提出修改方案；
- 请求范围（维持全部有效或部分有效）以用户确认为准，模板不自行扩大或缩小；
- 附图引用（"如下图所示：图X"）由内部流程提供已核验的附图，模板不自行编造附图内容；
- 本模板不自动生成 DOCX、PDF 或其他非文本文件。


## MBSE 追溯与条件论证补充

本模板的内部准备必须建立 R/F/S/B/E 链：R 为权利要求限定和答辩需求，F 为功能，S 为结构、步骤和关系，B 为输入输出、时序和行为，E 为直接证据、定位、日期、译文和技术效果证据。E 中证据与效果分开记录。内部链不得出现在对外正文。

独立权利要求的 N.1 为主题名称，N.2 起为技术特征；从属权利要求的 N.1 为首个附加特征。产品权利要求与方法权利要求分别分析。

支持、新颖性、创造性及其他理由按请求人实际主张顺序分开回应。新颖性必须逐份证据、逐项特征比对，不得跨证据拼接。创造性必须针对权利要求限定的整体技术方案，说明贡献特征与所解决技术问题、技术效果的 R/F/S/B/E 对应，并另行记录组合顺序、组合动机、接口、行为连续性、公知常识、技术偏见和相反启示。工程断点不自动推出法律结论；“特征很多所以必然创造性”等表达改为有证据边界的条件分析。

每个逐证据/逐特征对照表格的每一格均填写直接原文、页码/段落/图号/表号定位、比对结果或待核实说明，不得留空。二次或后续答辩逐项覆盖新增理由和证据。

法条、指南段号、权利要求修改规则、公开日、译文、公知常识、技术偏见和程序期限均须按案件时点逐案核验。当前有效专利法、2023 年专利法实施细则、当前专利审查指南、2025 年指南修改决定及具体程序通知只是核对对象，不因本模板而视为已核验。权利要求修改和最终请求范围须经用户明文确认。
