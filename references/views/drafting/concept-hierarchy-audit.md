# 上下位概念与关系审计标准

本文件是 `撰写视图` 在阶段1和阶段3中处理上下位概念的唯一规范性参考。MBSE 的技术事实、R/F/S/B/E模型和证据状态仍由 `MBSE 视图` 技能以 `mode=disclosure` 产生；本文件只规定这些结果如何进入保护单元、权利要求骨架和从属权利要求。

本文件中的“上位”“下位”不是单纯的词语宽窄判断，也不等同于权利要求编号的父子关系。每条关系必须同时记录关系类型、来源支持、替换结果、技术效果依赖和权利要求落位。

## 一、核心判断原则

对具体技术方案，优先按照下式展开：

```text
下位技术方案
= 上位技术角色/功能
  + 具体实现机制
  + 结构/行为关系
  + 必要条件或参数
```

只有同时满足以下条件，才可以把上位概念作为多个下位实现共同拥有的必要技术特征：

1. 技术问题和核心技术效果在相关下位实现中均成立；
2. 下位实现具有可替代性，替换后 `R→F→S→B/STATE→OutputState→E` 仍然闭合；
3. 上位概念覆盖的范围与原始材料真实披露的实现范围相符，不会无依据覆盖未披露、不能实施或不能产生相应效果的方案；
4. 上位概念没有隐藏下位实现之间的必要接口、时序、信号流、结构连接、控制条件或参数差异。

只要替换测试失败、技术效果依赖具体机制、差异位于必要结构/关系/行为/条件，或者上位概念会覆盖未支持方案，就必须保留下位概念，至少作为相应分支的必要特征。

不得因为下位概念更具体、客户当前产品采用该实现、某个实施例篇幅更长，或权利要求金标准使用了某个术语，就直接将该下位概念标为独立必要特征或把上位概念视为已获得支持。

## 二、关系类型必须分开

`relation_type` 只能从下表中选择；没有证据时不得默认使用 `is_a`。

| 关系类型 | 判断含义 | 典型例子 | 不得误写为 |
|---|---|---|---|
| `is_a` / `specializes` | 类型上的上下位或专门化 | 无线通信网络是通信网络的一种 | `part_of`、`implements` |
| `refines` | 对功能、行为、步骤、机制或技术角色的细化 | 基于导频符号执行信道估计细化为信道估计功能 | 类型继承 |
| `narrows` | 权利要求范围、数值范围、条件或参数的收窄 | 传输速率0～100收窄为20～50 | 类型继承、替换实现 |
| `part_of` | 组成、包含或结构隶属 | 信号处理模块属于通信处理设备 | `is_a` |
| `implements` | 结构、算法或机制实现功能 | 导频处理机制实现信道估计功能 | `is_a` |

`parallel_root` 不是上述五种技术关系，而是权利要求落位状态：同一技术链可以派生方法、设备、系统或存储介质等平行保护对象。平行保护对象不能仅因功能对应就互相提升、降级或合并为上下位概念。

### 2.1 关系类型的快速判断

依次回答：

1. “子概念”是否仍然是“父概念”所指类别的一种？是，才可考虑 `is_a/specializes`；
2. 如果不是，它是否是在同一功能上增加了处理机制、步骤、行为或约束？是，使用 `refines`；
3. 如果只是缩小范围、参数、阈值、数量、条件或时序窗口，使用 `narrows`；
4. 如果它回答“属于哪个部件/系统”，使用 `part_of`；
5. 如果它回答“由什么实现某项功能”，使用 `implements`；
6. 如果它回答“形成哪一种权利要求客体”，使用 `claim_impact=parallel_root_candidate`，不要伪造技术上下位关系。

## 三、上位概念准入与下位概念保留

### 3.1 上位概念准入

上位概念只有在“共同必要性、替换闭合性、支持范围”三项检查均通过时，才可以进入独立权利要求的共同必要特征。审计记录至少包括：

| 检查项 | 必须回答的问题 |
|---|---|
| 共同问题 | 相关下位实现是否解决同一 `R_problem` 或同一必要技术约束？ |
| 共同功能 | 是否具有相同的F角色、输入目标、技术变换和直接输出？ |
| 共同链路 | 替换下位实现后，S/B/STATE、接口、顺序和中间结果是否仍能衔接？ |
| 共同效果 | E的受影响对象、属性、条件和因果路径是否仍成立？ |
| 范围支持 | 上位概念是否覆盖了说明书实际披露而非想象的实现范围？ |
| 差异处置 | 下位实现之间的结构、信号、时序、参数或控制差异是否已经被正确标为替代或分支？ |

任一项为 `Q` 或无法回答时，上位概念只能标记为 `candidate/conditional`，不得标为阶段3技术语义 `pass`。

### 3.2 下位概念保留

下位概念必须至少作为分支必要特征保留的情形包括：

- 技术效果依赖该具体实现机制；
- 替换为另一实现后，功能、行为、接口、约束或效果因果链断裂；
- 区别位于必要结构、连接关系、信号流、时序、参数或控制机制；
- 上位概念会覆盖说明书未支持或不能实现技术效果的方案；
- 下位实现形成不同的实施主体、对象边界、状态迁移或独立执行路径。

多个下位实现能够共同承担同一上位功能时，应登记为 `alternative` 分支，不得把互斥实现并列累加为共同必要特征。

内部必要性状态只允许：

| 状态 | 含义 | 对权利要求的默认影响 |
|---|---|---|
| `common_necessary` | 所有相关实现共同需要 | 独立权利要求共同必要特征候选 |
| `branch_necessary` | 仅某一技术分支成立所必需 | 该分支的从属限定或平行根主题候选 |
| `alternative` | 可以相互替代的实现分支 | 保持为择一分支，不并列取并集 |
| `optional` | 不影响核心链闭合的可选特征 | 普通从属限定或说明书变体候选 |
| `Q` | 证据、范围或替换结果不足 | 保持待确认，不得直接消费为正式候选 |

这些状态是技术模型和撰写策略状态，不是确定性法律结论。

## 四、替换测试和效果测试

对每一条拟作为上位概括的关系建立替换测试：

```text
上位概念 U
├── 下位实现 L1
└── 下位实现 L2

用 L2 替换 L1 后，检查：
R_problem 是否仍相同？
F 的输入、变换和直接输出是否仍闭合？
S/B/STATE 的结构、接口、顺序和状态迁移是否仍成立？
OutputState 是否仍能形成？
E 的对象、属性、条件和因果路径是否仍成立？
```

审计结果使用：

- `passed`：替换后主链和效果链均闭合；
- `failed`：至少一项关键链路断裂，保留下位分支；
- `Q`：材料不足以判断，保持条件性；
- `not_applicable`：只有一个实现或没有可替代对象，不能据此证明上位概念可以泛化。

“功能名称相同”或“均能产生相似结果”不等于替换通过。必须核对输入、技术变换、接口、时序、输出状态和效果因果路径。

## 五、保护对象边界与概念层级分离

### 5.1 PST不是上下位概念树

一个 `PU` 可以派生多个 `PST`，例如：

```text
同一技术链
├── 通信数据处理方法
├── 通信数据处理设备
├── 通信数据处理系统
└── 存储介质
```

这些通常是平行保护对象。只有在技术材料明确支持独立对象边界、实施主体和闭合实施路径时，才分别登记为平行根主题。`PST`数量不得直接转换为独立权利要求数量，也不得把方法、设备、系统自动排列成父子层级。

### 5.2 对象字段与概念关系分离

以下字段回答不同问题：

| 字段 | 回答的问题 |
|---|---|
| `object_type` | 权利要求保护对象属于方法、设备、系统、组合物等哪一类别？ |
| `object_label` | 该对象在说明书中的完整名称是什么？ |
| `relation_type` | 两个技术概念之间是何种关系？ |
| `concept_status` | 下位实现对技术链的必要性是什么？ |
| `claim_impact` | 概念应进入独立项、从属项、平行根主题还是暂不消费？ |
| `reference_object_name` | 从属权利要求引用的直接上位客体完整名称是什么？ |

不能从 `object_type=method` 推导其是 `device` 的上位或下位，也不能从 `object_type=module` 推导其一定是 `system` 的下位类型。

### 5.3 电子通信类的特别边界

以下判断应作为默认起点：

- `通信网络 → 无线通信网络 → 5G通信网络`：在来源支持充分时，可以是 `is_a/specializes`；
- `通信网络 → 基站`：通常是 `part_of` 或参与关系，不是 `is_a`；
- `通信系统 → OFDM调制机制`：通常是 `implements` 或 `refines`，不是 `is_a`；
- `通信处理设备 → 信号处理模块`：通常是 `part_of`；
- `通信数据处理方法 ↔ 通信数据处理设备`：通常是平行保护对象，需分别登记对象边界；
- `输入数据 → 图像数据`：只有在类型范围意义上才是 `is_a`；“输入图像”也可能只是数据流角色，不当然是数据类型下位概念；
- “传输速率0～100”与“传输速率20～50”：属于 `narrows`，不是类型继承。

## 六、阶段1输出合同

阶段1在接收 MBSE `mode=disclosure` 结果后，除 R/F/S/B/E、CHAIN、PU、PST、CTX 和状态账本外，必须建立 `concept_relation_audit[]`。每条记录至少包括：

```text
concept_id
parent_concept_id
parent_label
child_label
relation_type
concept_status
common_role
lower_mechanism
structural_behavior_relation
required_conditions_or_parameters
source_phrase_spans
fact_status
replacement_test
effect_dependency
support_scope
claim_impact
decision_reason
audit_status
```

字段要求：

1. `relation_type` 必须是本文件第二节的受控值；不能空缺后默认 `is_a`；
2. `source_phrase_spans` 至少定位上位角色和下位实现的来源短语；
3. `replacement_test` 必须记录 `passed`、`failed`、`Q` 或 `not_applicable` 及理由；
4. `effect_dependency` 必须回答技术效果是否依赖下位实现；
5. `concept_status` 与 `claim_impact` 必须分别记录技术必要性和权利要求落位，不得合并为一个“重要/不重要”字段；
6. 任何 `Q`、`failed` 或来源范围不足的记录不得被阶段3静默提升为共同必要上位特征；
7. `part_of`、`implements`、`refines` 或 `narrows` 不得被转换成 `is_a`，除非另有独立来源支持真正的类型关系。

阶段1应同时输出“概念关系—CHAIN/PU/PST”的回指：上下位关系影响的是技术特征和分支组织，PST影响的是保护对象边界，二者不得相互替代。

## 七、阶段3生成和从属审计合同

阶段3生成 `source_claim_skeleton` 时：

1. 每个根主题和分支保留 `concept_relation_ids`；
2. 独立权利要求只能消费 `common_necessary` 且替换测试通过、支持范围充分的共同特征；
3. `branch_necessary` 和 `alternative` 必须保留分支关系，不能因文字概括被并入公共必要链；
4. `refines` 或 `narrows` 形成的从属增量必须保留继承锚点，不能用新增下位节点替换父项继承节点；
5. `part_of` 或 `implements` 只用于保留组成、接口和实现关系，不能把组成部件或实现机制改写成新的权利要求类型；
6. 方法、设备、系统或模块的对象边界发生变化时，先判断是否形成 `parallel_root_candidate`，不得用普通从属关系掩盖对象转换；
7. 每项从属权利要求除 `reference_target_claim_id`、`reference_object_name`、`reference_text` 和 `reference_name_match` 外，还应回指新增限定对应的 `concept_relation_ids`；
8. 从属项必须完整继承父项的对象、关系、条件、顺序和接口。只有增加下位限定而没有完整继承网络的，不得标记技术语义 `pass`。

从属权利要求的完整客体名称规则继续独立适用：不能以“方法”“设备”“系统”“装置”或“模块”替代直接上位权利要求的完整名称。客体名称完整不等于上下位关系正确，二者必须分别审计。

## 八、阻断条件和状态处理

出现下列任一情况时，阶段3至少保持 `conditional`、`[Q]` 或 `blocked`：

- 上下位关系缺少 `relation_type`；
- 以 `is_a` 作为默认关系，但来源只支持组成、实现或功能细化；
- 上位概念的替换测试为 `failed` 或无法判断；
- 下位实现决定接口、时序、信号流、状态迁移或技术效果，却被删除为普通可选项；
- 上位概念覆盖的范围超过说明书支持范围；
- 方法、设备、系统、模块之间发生未经记录的客体转换；
- 从属增量没有继承锚点，或将兄弟替代分支合并进当前路径；
- 概念关系没有来源短语、支持链接或效果因果路径；
- 金标准文本与概念关系不一致，但尚未完成人工语义核验。

只有当概念关系、保护对象边界、完整继承路径和支持关系同时闭合时，才允许阶段3技术语义轴标记 `pass`。这不等同于法律结论，也不等同于三本书籍原文逐句一致。

## 九、最小回归场景

上下位概念测试至少覆盖：

1. `is_a/specializes`：通信网络—无线通信网络—5G通信网络；
2. `part_of`陷阱：通信设备—信号处理模块；
3. `implements`陷阱：通信系统—OFDM调制机制；
4. `refines`：处理通信数据—基于导频符号进行信道估计；
5. `narrows`：宽参数范围—窄参数范围；
6. 方法、设备、系统的平行根主题；
7. 效果依赖具体机制的 `branch_necessary` 分支；
8. 两个可以相互替代但不能并列累加的 `alternative` 分支；
9. 说明书支持不足时的 `Q/conditional/blocked`；
10. 从属权利要求完整客体名称缺失与上下位关系同时错误的组合阻断。
