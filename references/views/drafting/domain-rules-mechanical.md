# 机械/结构域撰写规则

## 规则状态与文件边界

本文件已对齐标准撰写技能的通用接口，机械域的未决事项以 `[Q]` 保留。本文供阶段 1、阶段 3、阶段 5 和阶段 8 使用，适用于机械结构、装配、传动、支撑、导向、密封、定位、夹持、输送和制造设备。

本文件只规定机械技术方案的建模、权利要求撰写、说明书支持和文本审计。`DepPath`、`Sem_eff`、`DependentClaimTrace`、`ClaimTextAudit`、`SupportLink` 等对象的通用定义以对应合同文件为准；本文只规定机械域的使用方式，不建立第二套权利要求树。

版本、责任、审批、影响集和生命周期由第六章及通用治理接口处理。本文出现的 `pass/[Q]/fail/blocked` 只表示技术或文本核验状态，不表示授权、侵权或创造性法律结论。

## 一、机械域技术对象和证据要求

### 1.1 机械特征单元

| 单元 | 至少记录的内容 | 撰写和审计重点 |
|---|---|---|
| 构件/组件 | 零件、组件、装配层级和必要属性 | 是否有明确结构来源，不能以用途名称代替构件 |
| 连接关系 | 固定、活动、铰接、焊接、螺纹、卡接、传动连接 | 连接方式和相对位置是否清楚 |
| 位置关系 | 同轴、平行、垂直、内外、相邻、包围、前后 | 空间参照和安装基准是否明确 |
| 配合/接触 | 啮合、贴合、间隙、过盈、滚动、滑动、密封接触 | 接触条件是否为必要限定 |
| 运动关系 | 转动、平动、摆动、往复、连续、间歇、复合运动 | 输入、约束、输出和时序是否闭合 |
| 受力关系 | 动力源、驱动件、传递件、受力点、约束反力、输出件 | 力/力矩传递路径是否可回放 |
| 状态关系 | 初始状态、触发条件、中间状态、锁止/释放状态 | 状态转换条件是否明确并有支持 |
| 接口参数 | 尺寸、角度、节距、间隙、模数、孔距、压缩量 | 测量对象、基准、条件和范围是否明确 |
| 装配/工艺 | 装配顺序、安装条件、调整条件、加工关系 | 是否属于产品必要限定或独立方法步骤 |

构件名称、用途或外观相近，不等于结构、关系、行为和效果相同。附图只支持其明确表达的构件、连接或位置关系，不单独支持隐含尺寸、受力方向、运动顺序或材料性质。

### 1.2 机械 R/F/S/B/E 最小链

机械方案至少建立：

```text
R 技术问题
→ F 所需功能
→ S/REL 结构及其关系
→ B/STATE 行为和状态转换
→ E 技术作用或效果
```

涉及传动、驱动、支撑、夹持、密封、导向、变形或锁止时，至少回放：

```text
主动力源 → 驱动单元 → 接触/啮合区域 → 传递单元
→ 被驱动件 → 约束/反力 → 运动或状态输出 → 技术效果
```

“到达某一位置”不能同时替代行为、输出状态和技术效果；结构名称不能直接证明提高稳定性、降低磨损或避免泄漏。

## 二、独立权利要求撰写规则

### 2.1 产品权利要求

- 通常包括基础构件、特征性构件以及必要的连接、位置、配合、运动或受力关系；
- 连接关系应写明连接形式、相对位置和必要的运动/约束条件；
- 不以“固定装置”“驱动机构”“减震组件”等纯功能名称替代必要结构；
- 功能性限定并非一律排除，但必须能够由结构、行为或说明书支持；
- 未明确限定的“大”“小”“长”“高摩擦”等描述，不得自行转化为确定参数。

### 2.2 装配、加工和操作方法

- 只有在原始材料支持独立步骤顺序、实施主体和区别于产品边界的实施路径时，才形成方法权利要求；
- 正常按压、旋转、释放或使用动作不自动形成独立方法技术方案；
- 必要步骤应说明输入状态、操作顺序、结构变化和输出状态；
- 装配顺序只有在影响连接、定位、受力、密封或状态转换时，才作为必要限定。

### 2.3 独立性和主链

独立权利要求应保持 `R→F→S/REL→B/STATE→E` 的闭合。多个实施例只要保持相同的必要结构、关系、状态迁移和效果因果，应归入同一主链；不能按实施例数量机械增加独立权利要求。

## 三、从属权利要求和 MBSE 映射

### 3.1 完整从属对象

从属权利要求必须先沿每一条合法 `DepPath` 展开全部继承构件、关系、行为和条件，再识别本项 `DeltaSem`。本项有效语义是完整的 `Sem_eff`，不能只评价新增零件。

新增机械限定至少归入以下一类：

- 对既有构件或节点的结构细化；
- 对连接、位置、配合、运动、受力或参数关系的收缩；
- 与继承结构共同形成技术作用的协同限定；
- 与主链耦合并说明接口、行为变化的替代分支。

每一项新增限定都必须有继承锚点、机械作用或效果路径，并通过 `DependentClaimTrace` 记录。无锚点、无作用或无效果路径的细节不得消费为有效从权。

### 3.2 分支和多项从属

- 线性从属逐级累计全部上位限定，并分别记录每一级新增限定；
- 兄弟从属只继承共同上位网络，一个分支的构件、参数或效果不得进入另一个分支；
- 多项从属按每一个择一引用路径分别生成 `DepPath`、`Sem_eff` 和文本审计结果；
- 不得把多个上位权利要求的限定取并集；
- 参数或结构细化使用 `refine` 连接继承节点，不删除或替换继承节点；
- 已并入独立权利要求的特征，不得再次作为从权的独立贡献。

### 3.3 机械增量的作用分类

| 增量类型 | 机械写法 | 必要依据 |
|---|---|---|
| 结构细化 | 对既有构件、位置或连接作进一步限定 | 继承节点和结构关系 |
| 参数/关系收缩 | 限定节距、间隙、角度、孔距、压缩量等 | 测量基准、工作条件和范围支持 |
| 协同限定 | 新增特征与继承结构共同改变行为或效果 | 共同作用、因果链和原始支持 |
| 耦合替代 | 替代驱动、接触或支撑方式并保持可解释的主链联系 | 替代接口、行为变化和组合依据 |

### 3.4 MBSE 到权利要求的转换

| MBSE 内容 | 权利要求/说明书表达 |
|---|---|
| R 需求 | 具体机械工况和技术问题 |
| F 功能 | 构件或关系所发挥的技术作用 |
| S/REL 结构 | 构件、连接、位置和配合限定 |
| B/STATE 行为 | 工作过程、受力路径、运动路径和状态转换 |
| E 效果 | 由结构和行为支持的技术作用或可观察效果 |

模型节点编号、置信度和相似度只留在内部工作稿，不写入申请文件或对外答复。

## 四、说明书支持和机械效果归因

每一项权利要求特征和组合关系通过 `SupportLink` 定位到说明书、附图、实施例或实验材料。至少核对：

- 构件、连接、位置和配合是否有直接文字或明确附图支持；
- 受力、运动和状态转换是否有工作过程或结构机理支持；
- 尺寸、节距、间隙、孔距和压缩量是否有测量对象、方法、条件和端点依据；
- 效果是否由当前权利要求范围内的结构—行为链产生；
- 比较型效果是否有比较基准，不能以单一实施例结果覆盖全部范围；
- 材料、合金或参数路线是否同时具备组成/范围、作用机制、适用条件和效果因果。

没有充分依据时，效果只写“提供……结构基础”“适于保持……”或“能够减少……风险”，并将 `ClaimTextAudit` 标记为 `[Q]`。

## 五、机械域 ClaimTextAudit

调用通用 `ClaimTextAudit` 和 `SupportLink`，机械域至少检查：

| 审计项目 | 机械域问题 |
|---|---|
| 要素完整性 | 基础构件、特征构件和必要关系是否齐全 |
| 关系清楚性 | 连接、位置、配合、接触和空间参照是否明确 |
| 运动/受力闭合 | 动力源、传递件、约束、输出运动和状态是否连贯 |
| 接口/参数 | 测量对象、方法、工作条件、范围端点和匹配关系是否明确 |
| 从属完整性 | 是否继承全部上位限定，是否存在路径合并或分支泄漏 |
| 术语和先行词 | 构件名称、附图标记、指代和参数口径是否一致 |
| 支持关系 | 是否有说明书、附图或实施例可定位支持 |
| 效果归因 | 效果能否由结构—行为—状态链解释 |
| 修改一致性 | 修改后依存关系、结构方案和支持是否一致 |

审计状态只使用 `pass`、`[Q]`、`fail`、`blocked`。模型置信度或文本相似度不得单独使状态从 `[Q]` 升级为 `pass`。

## 六、机械域阻断条件

出现以下任一情形，至少标记 `[Q]`，必要时标记 `blocked`：

- 从属权利要求没有展开完整继承方案；
- 多项从属路径被合并或兄弟分支发生泄漏；
- 新增机械限定没有继承锚点；
- 关键受力、运动或状态链无法闭合；
- 参数没有测量对象、基准、条件或支持范围；
- 仅凭附图比例推断尺寸、受力或运动顺序；
- 功能性模块缺少结构、行为或说明书支持；
- 关键效果没有原始支持、比较基准或因果路径；
- 方法权利要求缺少步骤顺序、实施主体或产品边界差异。

|---|---|---|---|

| M-Q02 | 多构件联动方案的单侧实施主体边界 | 阶段 3 | 能明确执行主体、控制关系和侵权分析所需边界 |

## 八、受控回归的机械根主题分支

机械案件先按说明书确认对象根主题，再决定权利要求类型：

- 车辆、装置、设备或组合产品属于 device 根主题，使用 independent_device 或 dependent_device；具体车辆名称写入 object_label。
- 具有独立实施主体、输入状态、操作顺序和输出状态的控制/装配/制造链，才登记为 method 根主题，使用 independent_method 或 dependent_method。
- 方法步骤不能因为描述了装置的正常使用动作就自动成为独立方法；同样，方法根主题的步骤、执行主体和状态输出不能被压缩为装置从权的一句功能描述。
- 产品根主题和方法根主题都由说明书单独闭合后，分别保留为平行根主题；不得把方法项提升为产品项的第二项独权，也不得把产品分支强行塞入方法链。
- 机械分支的 branch_relation、parent_ref、source_phrase_spans 和 candidate_claim_ref 必须先冻结，再生成 type、depends_on 和 DepPath。
