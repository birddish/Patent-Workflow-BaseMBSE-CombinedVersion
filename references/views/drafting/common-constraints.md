# 共同约束、分轴状态与证据边界

本文档为阶段1至阶段8的共同约束，由 总入口规则 路由引用。

## 执业辅助提示

在每项实质性交付物的交付说明或独立审校附件中加入：`本内容仅为执业辅助参考，最终需专利代理师本人审核确认。` 对可直接进入专利申请文件的正文，不得将该提示语写入正文。

## 保密

保护保密信息；提示用户不要上传客户身份、无关商业秘密、未公开竞品敏感信息或撰写不需要的非公开材料。

## 不编造

不编造技术事实、对比文献、检索结果、实验数据、附图、标准、法律结论或实现细节。

## 技术问题→技术方案→技术效果闭环

始终保持"技术问题 -> 技术方案 -> 技术效果"闭环。对算法、软件、模型、数据结构或规则特征，说明其与技术特征的功能协同、技术对象及客观技术效果。

## 事实来源轴与撰写采用轴

不得把事实来源和撰写采用压缩为一个状态。完整状态合同见`protectable-unit-contract.md`。

| 轴 | 状态 | 核心规则 |
|---|---|---|
| `fact_status` | `[D]/[I]/[Q]/[X]` | `[D]`为明确记载，`[I]`为受限工程推断，`[Q]`为待核，`[X]`为排除 |
| `drafting_status` | `[D]/[N]/[G]/[Q]/[X]` | `[N]`仅限发明人或有权技术人员确认的新增事实；`[G]`必须回指`[D]/[N]`；`[Q]`不得进入正式母版 |

代理师负责法律表达、保护层级和策略确认，不得单独创造技术事实。操作日志或代理师确认不能把[I]自动升级为[D]或[N]。

## 主创新点锚定卡

在阶段1建立并全程维护，至少记录：

- CI 编号、候选创新点排序
- 原始证据位置
- 技术问题、技术效果
- 必要节点组、必要关系组
- 来源CHAIN、PU候选、PST和CTX
- 拟保护层级、拟权利要求落位
- 说明书实施支撑点
- 附图状态
- 是否允许与其他子链组合
- 权利要求锁定状态

主创新点或其必要因果链变更时，输出变更影响台账并将受影响下游成果标为待复核。

## 技术效果证据闭环

技术效果在内部记录中必须形成闭环：

`技术特征/协同关系 → B及STATE.OutputState → 受影响对象 → 受影响属性 → 技术后果E → 适用条件 → 证据状态`

无证据的性能数值、比例或比较结论不得写入申请文件。一般E可以是绝对技术后果；比较型E必须记录比较基线、差异方向和适用范围。E节点原则上用于说明书效果论证，不因其名称当然成为权利要求特征；`F.Output`或`STATE.OutputState`也不得直接复制为E。

## 四层映射账本

建立并维护`MBSE节点/关系 → CHAIN/PU/PST/CTX → CF/REL/CT/INT → 母版及提交候选版权项`四层映射账本。详见`node-claim-mapping.md`。

阶段3仅改变文字表述、语序或不改变技术含义的术语时，只更新映射账本；改变PU、PST、CTX组合、特征取舍、必要关系或主创新点时，必须按映射规则回写阶段1，并在影响IU、对象边界或检索单元时回退阶段2补检。
