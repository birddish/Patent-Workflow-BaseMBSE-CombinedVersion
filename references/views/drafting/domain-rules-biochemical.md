# 生化/材料域撰写规则

## 规则状态与文件边界

本文件已对齐标准撰写技能的通用接口，生化/材料域的未决事项以 `[Q]` 保留。本文供阶段 1、阶段 3、阶段 5 和阶段 8 使用，适用于化合物、组合物、药物、生物技术、生物序列、材料配方、食品/化妆品和制备工艺。

本文只规定生化/材料技术对象的建模、权利要求撰写、说明书支持和文本审计。`DepPath`、`Sem_eff`、`DependentClaimTrace`、`ClaimTextAudit`、`SupportLink` 等对象的通用定义以对应合同文件为准；本文不建立第二套权利要求树。

版本、责任、审批、影响集和生命周期由第六章及通用治理接口处理。本文出现的 `pass/[Q]/fail/blocked` 只表示技术或文本核验状态，不表示授权、侵权或创造性法律结论。

## 一、生化/材料域技术对象和证据要求

### 1.1 特征单元

| 单元 | 至少记录的内容 | 撰写和审计重点 |
|---|---|---|
| 化合物/分子结构 | 通式、取代基、立体构型、盐型、晶型、序列、分子量 | 身份、结构和编号是否明确 |
| 组分 | 必要/可选组分、纯度、来源、相态、功能 | 组分是否真实存在且具有技术作用 |
| 含量/比例 | 质量百分比、重量份、摩尔比、浓度、配比 | 单位、端点和范围是否一致 |
| 工艺步骤 | 原料加入、反应、分离、纯化、后处理 | 步骤顺序和实施主体是否明确 |
| 工艺条件 | 温度、时间、压力、pH、溶剂、催化剂、气氛 | 条件窗口和前后步骤是否兼容 |
| 状态变化 | 溶解、反应、相变、结晶、聚合、纯化或生物活性状态 | 中间状态、触发条件和输出状态是否可回放 |
| 参数/表征 | 粒径、黏度、分子量分布、纯度、谱图或活性数据 | 测量对象、方法、条件和基线是否明确 |
| 用途 | 产品、用途对象、使用条件和技术作用 | 产品、用途与效果是否混同 |

组分名称、结构相似、功效标签或范围重叠不能代替身份、相态、反应路径、工艺条件和效果证据。

### 1.2 生化/材料 R/F/S/B/E 最小链

```text
R 技术问题
→ F 组成/反应/制备/用途功能
→ S 组分、分子结构、材料结构和工艺实体
→ B 反应路径、工艺顺序、状态变化或使用过程
→ E 产率、纯度、活性、稳定性、选择性、粒径、黏度或用途效果
```

效果必须能够回指当前权利要求范围内的组成、结构、工艺、条件或用途；不能把单一实验结果直接泛化为全部范围。

## 二、独立权利要求撰写规则

### 2.1 化合物、组合物和材料产品

- 化合物权利要求应明确结构、必要取代基、盐型/晶型或序列等身份要素；
- 组合物权利要求应明确必要组分、含量/比例及必要的状态或相容性条件；
- “包含”是开放式表述，“由……组成”是封闭式表述，“基本上由……组成”只能允许不改变基本特性的组分；
- 含量单位应统一为质量百分比、重量份、摩尔比或其他明确单位；
- 材料和配方必须说明组成、结构、适用条件与可观察性能之间的关系；
- 不以“具有良好性能”“治疗有效”等未定义词语替代可验证的组分、条件或参数。

### 2.2 制备、合成和纯化方法

- 必须写明原料、加入/反应/分离/纯化/后处理步骤以及必要顺序；
- 对温度、时间、压力、pH、溶剂、催化剂、气氛等条件，说明其对应步骤和作用；
- 只有当步骤顺序、条件或过程状态影响产品或技术效果时，才作为必要限定；
- 产品—工艺特征不能替代产品本身的必要结构或组成，除非原始材料能够证明工艺导致可识别的产品差异；
- 方法权利要求的实施主体、输入状态和输出状态应可识别。

### 2.3 用途、药物、生物序列和 Markush

- 用途权利要求应明确产品、用途对象、使用条件和技术作用；
- 药物用途应区分产品特征、用途限定和治疗效果，不以效果标签替代必要产品或使用条件；
- 生物序列应保持序列身份、序列表、长度、同一性/功能性限定与支持依据一致；
- Markush 选择必须有共同结构/性质、选择方向和实施例支持；
- 不能仅因通式覆盖多个成员，就推定每一个具体成员均有充分支持或相同效果。

## 三、从属权利要求和 MBSE 映射

### 3.1 完整从属对象

从属权利要求先沿每一条合法 `DepPath` 展开全部继承的组分、结构、工艺、条件、用途和效果约束，再识别本项 `DeltaSem`。有效对象是完整 `Sem_eff`，不能只评价新增组分、数值或工艺步骤。

新增限定至少归入以下一类：

- 新增或替换组分，并说明身份、相态和技术作用；
- 含量、比例、参数或工艺窗口收缩；
- 结构、序列、盐型、晶型或材料形态细化；
- 反应步骤、加入顺序、纯化方式或状态转换细化；
- 与继承组分/工艺共同产生效果的协同限定。

每项新增限定必须有继承锚点、技术作用或效果路径，并通过 `DependentClaimTrace` 记录。

### 3.2 分支和多项从属

- 线性从属逐级累计全部组分、结构、条件和用途限定；
- 兄弟分支只继承共同上位网络，一个分支的组分、参数、工艺或效果不得进入另一个分支；
- 多项从属按每一个择一引用路径分别生成 `DepPath`、`Sem_eff` 和审计结果；
- 不得把多个上位权利要求的组分、工艺条件或用途限定取并集；
- 参数、范围或工艺细化使用 `refine` 连接继承节点，不删除或替换继承节点；
- 已经并入独立权利要求的组分或工艺条件，不得再次作为从权的独立贡献。

## 四、参数、工艺窗口和说明书支持

### 4.1 参数和测量方法

每个数值范围至少明确：

1. 测量对象、参照基准和单位；
2. 测量方法、仪器或测试条件；
3. 范围端点、优选范围和实施例覆盖；
4. 参数与结构、组成、工艺或性能的关系；
5. 不同测量方法是否会产生不可比结果。

不得把“高纯度”“低黏度”“良好活性”等未经定义的描述直接转化为权利要求参数。

### 4.2 组分相容性和工艺连续性

组合物和工艺至少检查：

- 组分之间是否会反应、失活、沉淀或发生相态冲突；
- 工艺步骤的加入顺序、温度、pH、溶剂和催化剂是否能共同满足；
- 中间体或状态变化是否有原始文件支持；
- 效果是否来自当前组合，而不是未写入权利要求的额外条件。

### 4.3 支持和效果

通过 `SupportLink` 将组分、结构、工艺、参数、用途和效果定位到说明书、实施例、对比例、谱图或实验材料。通过 `EffectEvidenceCard` 记录效果来源、比较基准、来源日期和权利要求范围覆盖。没有比较基准、端点支持或组合依据时，标记 `[Q]`，不得以模型相似度或预测活性代替证据。

## 五、生化/材料域 ClaimTextAudit

调用通用 `ClaimTextAudit` 和 `SupportLink`，至少检查：

| 审计项目 | 生化/材料域问题 |
|---|---|
| 身份完整性 | 化合物、组分、序列、盐型、晶型或材料结构是否明确 |
| 组成和含量 | 必要组分、开放/封闭式表述、单位、比例和端点是否一致 |
| 工艺顺序 | 原料、步骤、条件、中间状态、分离和后处理是否闭合 |
| 参数可测性 | 测量对象、方法、条件、单位和范围是否明确 |
| 相容性/连续性 | 组分、条件和步骤能否共同满足 |
| 从属完整性 | 是否继承全部上位限定，是否存在路径合并或分支泄漏 |
| 术语和编号 | 化学名称、序列编号、组分名称和用途指代是否一致 |
| 支持关系 | 说明书、实施例、对比例、谱图或实验依据是否可定位 |
| 效果归因 | 效果是否归属于当前组合并覆盖权利要求范围 |
| 修改一致性 | 修改后组成、工艺、用途、依存关系和支持是否一致 |

审计状态只使用 `pass`、`[Q]`、`fail`、`blocked`。模型置信度、预测活性或文本相似度不能单独升级审计状态。

## 六、生化/材料域阻断条件

出现以下任一情形，至少标记 `[Q]`，必要时标记 `blocked`：

- 从属权利要求没有展开完整继承方案；
- 多项从属路径被合并或兄弟分支发生泄漏；
- 新增组分、结构、工艺或参数没有继承锚点；
- 化合物或组分身份、相态、盐型、晶型或序列不明确；
- 参数缺少测量对象、方法、工作条件或端点支持；
- 工艺步骤、条件、加入顺序或中间状态无法闭合；
- 组合物存在相容性或反应冲突而未说明处理条件；
- 效果没有比较基准、原始支持或范围覆盖；
- Markush 具体选择缺少共同性质、选择方向或实施例支持；
- 只有预测活性、模型相似度或单一实施例结果，没有可核实的组合依据。

## 七、域特定待确认门

以下事项保留为 `[Q]`，逐案核实后再更新规则：

| 编号 | 待确认事项 | 影响阶段 | 通过条件 |
|---|---|---|---|
| C-Q01 | Markush 选择的支持依据与单一性 | 阶段 3 | 共同结构/性质、选择方向和实施例能够对应 |
| C-Q02 | 黏度、分子量分布等参数的测量方法一致性 | 阶段 3 | 测量对象、方法、条件和换算关系明确 |
| C-Q03 | 生物序列格式和序列表要求 | 阶段 3 | 序列身份、编号、长度和功能性限定一致 |
| C-Q04 | “治疗有效量”等功能性含量限定的清楚性 | 阶段 3 | 含量、对象、测量或验证方式可识别 |
| C-Q05 | 食品/化妆品组合物功能性限定的可验证性 | 阶段 3/5 | 组成、用途条件和客观效果能够支持 |
| C-Q06 | 组合物中含量为零的表述 | 阶段 3 | 开放/封闭式范围和排除关系明确 |
| C-Q07 | product-by-process 对产品本身的限定作用 | 阶段 3 | 工艺导致的可识别产品差异有原始支持 |
| C-Q08 | 生化域 MBSE 视图的选择和适配 | 阶段 1 | 组分—工艺—性能链与四层映射保持一致 |

## 八、受控回归的生化/材料根主题分支

生化/材料案件按产品身份、工艺链和用途对象分开锁定根主题：

- 化合物、组合物或材料产品只有在身份、必要组分/结构、范围和作用链闭合时登记为 composition、compound 或 material 根主题。
- “上述组合物的制备方法”默认是以组合物为父节点的 preparation_method 分支；只有说明书明确给出独立原料输入、步骤顺序、实施主体和产品输出，才登记为 independent_preparation_method。
- “上述组合物的应用/用途”默认是以产品为父节点的 use 分支；用途对象、使用条件和技术作用没有独立闭合时，不得提升为 independent_use。
- 组合物的配方变体、含量窗口、工艺条件和用途分支不得因共享产品名称而合并；各分支分别记录直接引用集合和回退价值。
- 领域对象名称不改变 type 枚举；应使用 object_type 加 object_label 表达，来源短语和 unsupported_additions 单独审计。
