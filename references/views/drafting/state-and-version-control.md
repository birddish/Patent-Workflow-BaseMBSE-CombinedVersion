# 状态台账、版本母本与最终组卷控制

## 状态定义

每一阶段确认单及总台账只能使用以下状态：

| 状态 | 含义 | 可否进入下一阶段 |
|------|------|-----------------|
| 草稿 | 初稿，未经代理师审阅 | 否 |
| 待确认 | 已提交代理师审阅，等待反馈 | 否 |
| 确认 | 代理师明确确认 | 是 |
| 退回修订 | 代理师要求修改 | 否，需修订后重新确认 |
| 已替代 | 被新版本替代 | 否 |

阶段6、阶段7额外可用：未启动。

**待确认不构成进入下一阶段、组卷或出件的依据。**

## 版本台账

台账至少记录以下文件的文件名、版本/日期、状态、依赖关系和受影响下游阶段：

- 技术交底书
- 已确认权利要求 Markdown
- 背景技术
- 具体实施方式
- 附图语义源（如已启动）
- 最终 DOCX

以项目文件和版本记录为事实来源，不得以对话过程替代项目事实。

台账另行记录四层映射账本、PU准入矩阵、母版分配表、依赖图和阶段5步骤/模块主表的文件、版本、状态及最终DOCX核验结论；不得以权利要求特征级压缩表替代节点级映射。

## 变更影响台账

权利要求、说明书或附图的题名、术语、编号、技术关系或逻辑顺序发生变化时，登记变更影响台账，将相关下游成果标为待复核。

仅纯版式且不改变文本、图示或引用关系的调整，可以登记为有限复核。

## 最终 DOCX 母本链

最终 DOCX 的权利要求文本以阶段3已确认的权利要求 Markdown 为**唯一文字母本**；说明书和附图分别以已确认的对应母本为准。

组卷中的手工改动必须逐项登记，并触发与文字母本、图源及下游文件的一致性复核。

最终 DOCX 出件前必须由阶段8完成"母本一致性与图文语义"审计：

- 核对题名、全部提交候选权利要求、关键术语、说明书章节、附图数量和图号、模块名称、流程步骤、数据流及反馈箭头
- 以阶段5步骤/模块主表核对步骤编号、模块名称和权利要求映射
- 扫描重复字、错别字、残留占位符、标题回退和未登记的手工改写
- 附图流程已启动时，核对附图语义源规划数量与 DOCX 嵌入数量
- 无法完成视觉核验时，只能记录为未核验，不得标记出件通过

## 阶段8 配套台账

若案件为完整新撰写模式，台账还须逐一记录阶段1至阶段5、阶段8的状态。既有申请文件独立审计模式只建立阶段8台账、审计报告和补强包。

阶段1至阶段5的材料未提供时必须登记"未提供"，阶段6、阶段7未启动时登记"未启动"，不得虚构已经完成或确认。
