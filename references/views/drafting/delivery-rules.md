# 交付规则

## 交付格式

以可复用的 Markdown 交付表格、清单、权利要求、说明书、Mermaid 源图和 VSDX 图。保持术语、步骤编号、实施例编号和图号一致。

## 硬换行规则

输出 Markdown 时，对权利要求技术特征、方法步骤、模块条目及分号结束的连续内容使用"两个半角空格 + 换行"的硬换行。不得仅用空白段落模拟换行，以避免 LibreOffice、Word 或 WPS 转换时内容挤合。

示例：

```markdown
S1：获取目标图像数据；  
S2：对所述目标图像数据进行特征提取，得到特征图；  
S3：基于所述特征图进行目标检测，得到检测结果。  
```

## 正文与审校分离

阶段5的申请文件正文与内部审校材料必须**分开交付**：

- **申请文件正文**：只写术语说明、实施例、具体实施方案、对实施方案的必要扩展说明以及技术效果
- **内部审校附件**：写权利要求映射、技术交底证据、追溯链、MBSE 节点、证据状态、待确认问题和质量检查结果

下列内容只进入审校附件或交付说明，**不得进入可直接粘贴的说明书正文**：

- MBSE、追溯链编号、节点编号（R-xx、F-xx 等）
- 权利要求映射表、证据状态标记
- `[Q]`、待确认问题和阶段确认单
- "来源于技术交底书""内部追溯结果"等撰写过程用语
- 执业辅助提示

## 待确认标记

对任何待确认事实、缺失实现机制、性能指标、检索边界或效果因果关系使用 `[Q]` 或"待确认"标记，不以推测补足。

## 阶段8 交付物边界

阶段8 审计确认后可按总流程索引进行摘要、附图说明、最终组卷和形式审查。阶段6、阶段7 未启动时，不得将其列为完成前提。该收尾工作不替代默认主链的确认。

## 最终 DOCX 出件前审计

最终 DOCX 出件前必须由阶段8 完成母本一致性与图文语义审计（详见 `state-and-version-control.md` 和 `stage-8-existing-application-audit.md`）。
