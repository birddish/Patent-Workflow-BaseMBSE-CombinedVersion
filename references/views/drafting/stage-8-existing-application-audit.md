# 阶段 8：既有申请文件审计与补强建议

## 适用范围

本阶段用于阶段5完成后的默认最终审计，或对已有中国专利申请文件开展独立审计。阶段6、阶段7仅在用户明确启动附图流程时作为补充输入，不是本阶段前置条件。适用于机械/结构、电子通信/AI/软件和生化/材料全部M/E/C领域。仅提供既有申请文件时，可以独立启动；不得据此声称阶段1至阶段5已完成、已确认或具备相应证据。

本阶段不作确定性授权、无效、侵权、新颖性或创造性结论；检索需求按阶段 2 处理。

## 输入与版本登记

本节的版本登记只用于固定本次技术审计所读取的输入和标识待复核对象；版本替代、生效、责任、审批和影响集合的完整治理记录统一写入第六章，不在阶段8重复定义。

建立文件登记与版本台账，至少登记：

| 文件类别 | 最低输入 | 未提供时的记录 |
|---|---|---|
| 技术来源 | 技术交底书、补充技术材料、版本信息 | “未提供”，并列入来源审计限制 |
| 申请文件 | 权利要求书、说明书、摘要、附图及可用源文件 | 标明缺件和无法核验范围 |
| 过程文件 | 已有阶段1至阶段5及阶段6至阶段7（如已启动）输出、确认记录、检索记录 | 阶段1至阶段5未提供时记为“未提供”；阶段6、阶段7未启动时记为“未启动”，不得倒推已完成 |
| 最终组卷母本 | 已确认权利要求Markdown、说明书Markdown、附图语义源（如已启动）及其版本 | 缺少时不得声称已完成母本一致性审计 |
| 最终DOCX | 待出件DOCX、嵌入图片清单和生成/手工改动记录 | 缺少时仅能审计已有材料，标明未完成最终出件审计 |

开案时同时登记案件模式：完整新撰写、既有申请文件独立审计或锁定权利要求的说明书补强。对完整新撰写案件，本阶段只记录内容核验状态`pass/[Q]/fail/blocked`及阻断原因；待确认不构成组卷或出件依据。版本替代、回退、生效、审批和责任字段由第六章治理接口登记，不在阶段8另行定义。

## 审计方法与分轴状态账本

逐一将申请文件的技术特征、技术事实和判断性术语映射到交底书或补充材料。状态执行`protectable-unit-contract.md`，不得用一个D/N/G/Q/X字段混合事实来源和撰写采用。

| 轴/状态 | 判定标准 | 必要证据或处理 |
|---|---|---|
| `fact_status=[D]/[I]/[Q]/[X]` | 明确披露、受限推断、待核或排除 | 定位页码、段落、图号、版本及推断前提 |
| `drafting_status=[D]/[N]/[G]/[Q]/[X]` | 撰写采用方式 | N须有发明人或有权技术人员、日期和实施依据；G须回指D/N |
| `drafting_admission` | PU进入、附条件进入、暂停、排除或待核 | 记录准入理由、当前落位和重启条件 |

相对于交底书新增的技术事实，只有经发明人或有权技术人员确认后才能在撰写轴标为N，不等同于相对于现有技术具备新颖性或创造性。代理师不能单独创造N类技术事实。未确认内容在事实轴标I或Q、在撰写轴按Q控制。

每项N类内容须单列技术问题、输入或触发条件、处理规则、输出状态、异常边界、技术效果及发明人或有权技术人员确认记录。缺少实施依据时先记为Q，并提出确认问题；不可用来源审计替代现有技术检索。

## 必交付审计件

### 覆盖与来源矩阵

输出两张可追溯矩阵：

1. 技术交底书→申请文件覆盖矩阵：交底中的主技术链、可选分支、参数、效果和图示分别对应至权利要求、说明书、摘要和附图；未覆盖项说明是否应补充、舍弃或确认。
2. 申请文件→技术交底书来源矩阵：每项实质技术特征分列`fact_status`、`drafting_status`、原始证据、技术确认人/日期、保护层级和说明书位置；
3. 主创新点纵向审计矩阵：主创新点、来源CHAIN、准入PU、PST、CTX、权利要求/说明书/附图/效果位置、分轴状态、问题等级及处理；
4. 四层追溯矩阵：MBSE节点/关系、CHAIN/PU/PST/CTX、CF/REL/CT/INT、母版与提交候选版权项、说明书/附图、映射状态及缺口处理；
5. CTX组合与单一性审计：跨实施例组合依据、共同属性、作用依据、互斥条件、PU分组、暂停/另案处理及结论；
6. 独权反向审计：每项独权定位至CHAIN、准入PU、PST和CTX，并核对PST客体完整性。

### 三向支持审计

按“权利要求—说明书—附图”逐项审计：

1. 权利要求的每项技术特征在说明书中是否有可定位的实现方式、输入输出、条件和技术效果；
2. 说明书中的核心流程、并列技术分支、模块和数据状态是否与附图标号、流程箭头和图示一致；
3. 附图是否遗漏权利要求中的核心模块，是否存在标号不一致、流程方向错误、正文未解释的图示或正文混入内部审校标记。
4. 已采用节点、必要关系、CF/REL/CT/INT及主创新点是否正确落位；全部跨实施例组合是否有CTX依据；暂停或排除PU是否误入申请文件。
5. 权利要求依赖图是否通过编号、在前引用、择一引用、多项从属限制、路径兼容、继承锚点、跨组误引和静默替换审计。

特别核验编辑、渲染、局部重绘、工程导出、参数补全等平行分支，避免被不当合并为一条必经流程。

### 权利要求文本审计与支持链接

对每项提交候选权利要求及其每条从属引用路径生成`ClaimTextAudit`。从权必须先展开`DepPath`和`Sem_eff`，再检查本项增量；不得把附加特征单独作为审计或法律评价对象。至少逐项检查：要素完整性、关系与条件、依存关系、先行词/术语、清楚性/范围、说明书/附图/实施例支持、效果归因和修改一致性。

支持矩阵采用`SupportLink`记录`claim_span`、`description_id`、`relation_type=itself/description/example`、候选`confidence`、附图/结构式/序列表/实验锚点和`human_decision`。模型相似度、主题距离、ROUGE、BERTScore或置信度只能用于发现候选位置；没有可定位原文或组合依据时，状态必须为`[Q]`、`fail`或`blocked`。

多项从权必须逐路径核查继承完整性和分支隔离；出现路径合并、兄弟泄漏、无继承锚点、无作用/效果路径、支持仅靠相似度或只审计`ΔSem`时，至少登记P1，必要时阻断最终出件。模型输出与人工判断分栏保存，详细版本、责任和审核事件进入第六章治理台账。

### 最终DOCX母本一致性与图文语义审计

最终DOCX出件前，逐项建立“母本—最终件”比对表：

| 审计对象 | 文字或图示母本 | 最终DOCX核对项 | 结论/问题等级 | 处理 |
|---|---|---|---|---|
| 题名及章节 | 已确认文件名称和说明书母本 | 题名、章节名称、摘要及附图说明 |  |  |
| 全部提交候选权利要求 | 阶段3已确认权利要求Markdown | 全文、编号、依赖图、术语及未登记改动 |  |  |
| 说明书 | 已确认背景技术和具体实施方式Markdown | 章节、术语、关键技术链及插入内容 |  |  |
| 步骤/模块 | 阶段5步骤/模块主表 | 步骤编号、模块名称、输入输出、条件、权利要求映射及实际段落位置 |  |  |
| 附图 | 附图语义源及图源核对记录（如已启动） | 图号、数量、模块、步骤、数据流和反馈箭头 |  |  |

至少扫描重复字、错别字、残留占位符、标题回退、术语回退、图号遗漏和未登记的手工改动。附图流程已启动时，核对图源规划数量、已生成图片数量和DOCX嵌入数量；逐图确认模块名称、流程步骤、数据流及反馈箭头与说明书一致。不能自动或人工完成页级视觉检查、嵌入图检查或语义核对的项目，必须标为“未核验”，不得以“通过”替代。

### 写作与形式审计

审计背景技术—技术问题—主创新点的逻辑闭环，术语和数据状态的一致性，判断性术语的可实施性，以及摘要、附图、说明书、权利要求之间的对应关系。以阶段5步骤/模块主表为唯一基准核验最终DOCX的步骤编号、模块名称及权利要求映射，防止步骤引用、归属或编号漂移。DOCX应做页级视觉核验；无法自动渲染时，记录限制并要求在WPS/Word中人工复核。形式清单至少包括：摘要不超过300字（含标点）、空白页、批注、高亮、修订痕迹、图文流程方向、图号标号一致性；阶段6、阶段7未启动或附图未提供时，仅记录相应审计边界，不阻断文字审计。

问题按以下优先级分类：

| 级别 | 含义 | 示例 |
|---|---|---|
| P0 | 阻断最终出件或导致最终件无法追溯至已确认母本的问题 | 已确认权利要求与最终DOCX不一致、关键图源规划与嵌入图不一致、锁定权利要求被未登记改写 |
| P1 | 可能影响技术方案成立、支持、保护主题或图文技术对应的重大问题 | 关键特征无来源、PST不完整、跨实施例组合无CTX、暂停PU误入、独立替代链被降格或平行分支错误合并 |
| P2 | 必须修正的一致性或形式问题 | 术语、数据状态、图文对应、摘要字数或效果链缺口 |
| P3 | 形式、表述或版式优化问题 | 标题、编号、样式、交叉引用、页级版式 |

### 说明书补强包

除非用户明确要求修改权利要求或原文件，固定输出“定位原文 + 替换/插入位置 + 可直接粘贴正文 + 来源状态 + 影响文件 + 内部依据说明”。锁定权利要求时必须提示说明书补强不能扩大既有保护范围。对质量评分、完整度、优先级、路径选择、回退、参数补全等术语，正文必须交代含义、输入、规则、触发、输出、异常边界和后续作用。N 类正文还需覆盖技术问题、处理机制、冲突处理、人工校正入口和技术效果。

可采用“主实施例 + 成组优选实施方式”，不必为每项从属权利要求机械复写整套主流程；内部映射仍须保证逐项支持。

## 确认与回退

终审形成申请文件审计确认单，至少包含：本次输入版本快照（详细版本台账由第六章治理接口维护）、母本—最终件比对表、主创新点锚定卡、四层追溯矩阵、独权反向定位、CTX组合与单一性审计、依赖图、暂停/排除PU检查、步骤/模块主表、分轴状态统计、P0/P1/P2/P3关闭情况、遗留风险和阶段6/7状态。确认单必须给出“可提交”“限说明书、附图或编排修改后可提交”或“不可提交”的内容结论；存在P0、依赖图阻断项或未核验的母本一致性/图文语义项目时，不得给出“可提交”。责任确认、审批和生命周期记录交由第六章保存。

| 审计发现 | 回退阶段 |
|---|---|
| 新增技术内容、来源缺失、主技术问题变化 | 阶段 1；涉及检索布局时同步阶段 2 |
| 需调整权利要求层级、保护主题或特征组合 | 阶段 3 |
| 背景、实施方式或技术效果支撑不足 | 阶段 4 或阶段 5 |
| 图文不一致、页级版式或绘图问题 | 登记为附图待处理事项；仅在用户明确授权后启动阶段6或阶段7 |
| 用户锁定权利要求 | 仅阶段 5 生成补强包，不主动改写权利要求 |
| 最终DOCX与母本不一致、图源数量或语义不一致、文本异常 | 在阶段8登记P0/P1/P2并回到最早受影响阶段；锁定权利要求时仅提出说明书、附图及最终排版修改建议，不改写权利要求 |

本内容仅为执业辅助参考，最终需专利代理师本人审核确认。

## 文献和自动化审计边界

清楚性、支持关系、drafting alignment 和 definiteness 研究可用于扩展风险清单和候选位置发现，但不同法域的术语和法律效果不得直接移植为中国法结论。`ClaimTextAudit` 至少应逐项核验要素、关系/条件、依赖、先行词、范围、`SupportLink` 原文位置、效果归因和修改一致性；语义相似度或自动评分没有原文锚点时，状态保持 `[Q]` 或 `blocked`。AI 只能提出候选缺口，关闭 P0/P1 审计项仍须代理师确认。
