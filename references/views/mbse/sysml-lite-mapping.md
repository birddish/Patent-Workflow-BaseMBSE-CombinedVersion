# SysML-lite MBSE 映射

> 本文件为 `MBSE 视图` 全模式 通用的 SysML-lite 语义参考。所有 Mode 均使用 R/F/S/B/E 五层模型；document mode 中的 C（上下文接口）和 P（约束）已映射至 R/F/S/B/E 对应层（参见 `modes/mode-document.md` 的 C/P 映射规则）。

本参考文件增加了更严格的 MBSE 语义，而不要求完整的 SysML 标注。使用它来防止五层模型变成松散的专利提纲模板。

## 1. 视角语义

| MBSE 要素 | 专利面向的视角 | 含义 | 不得用于 |
|---|---|---|---|
| 需求（Requirement） | R | 技术需求、约束、验收目标、运行条件 | 最终技术效果或商业目标 |
| 功能/活动（Function/Activity） | F | 满足R所需的输入—技术变换—直接输出合同 | 不含动作的组件名称、技术效果或唯一实现结构 |
| 逻辑/物理块（Logical/Physical Block） | S | 分配给 F 的物理、逻辑、数据、电路、软件、网络或材料结构 | 无接口的裸特征列表 |
| 行为（Behavior） | B | 序列、状态转换、控制逻辑、反应/工艺路径、交互协议 | 以叙述方式重复的静态结构 |
| 效果/验证目标（Effect/Verification target） | E | 由S/B/关系及输出状态进一步造成的对象属性变化或技术后果 | F或OutputState的同义改写、无依据的可专利性结论 |

## 2. 分配规则

对每个实质性功能，说明由哪个结构实现：

```text
F-id -> 分配给 -> S-id
```

如果多个结构共同实现一个功能，识别它们之间的接口。如果一个结构支持多个功能，分别列出每个分配。

每个F同时记录`SystemBoundary/Input/Transformation/Output/PreconditionOrTrigger`。`F.Output`是功能规格，不是独立O层；具体B的`STATE.OutputState`用于核验功能是否实现。

以下情况拒绝通过或标注 `[Q]`：

- 功能没有实现结构；
- 结构在追溯链中没有功能；
- 行为使用了未分配给相关功能的结构。

## 3. 接口规则

结构之间的每条重要箭头必须标识接口类型：

- 物料流：原料、流体、气体、样品、产品、组件；
- 能量流：电能、热能、机械力、压力、光；
- 信号/数据流：传感器信号、控制指令、数据包、元数据、模型输出；
- 控制流：触发、决策、授权、反馈、时序条件；
- 机械关系：接触、啮合、铰接、滑动副、导向、约束、力传递路径。

当技术贡献依赖于接口时，不得写"连接"或"交互"等通用箭头。

## 4. 行为选择

根据技术内容选择行为形式：

- 活动/流程模型：有序过程、算法、制造方法、操作方法。
- 时序模型：多模块消息交换、通信协议、API/工作流交互。
- 状态模型：模式切换、阈值决策、故障处理、生命周期状态。
- 参数关系：公式、阈值、比例、几何、性能约束。

如果交底书对某个声明的结构缺少行为信息，将行为标注为 `[Q]`，并向发明人询问什么操作步骤使该结构具有技术意义。

## 5. 验证边界

对每个E记录受影响对象、受影响属性、技术后果、适用条件、S/B/关系及OutputState因果路径、证据和效果类型。效果类型为`absolute`或`comparative`；只有后者必须记录比较基线、条件和口径。证据状态记录以下之一：

- 已公开的测试/测量；
- 已公开的定性效果，有结构/行为支持；
- 有列明前提的工程推断；
- `[Q]` 待确认。

不得在本 内部视图 内将 `E` 转化为新颖性、创造性或权利要求范围结论。

若E与F使用相同动作和对象、仅表述“实现了F”、没有受影响属性，或者可以脱离具体S/B/关系而成立，则删除该E、将内容移入`F.Output`或标`[Q]`。

## 6. 最小追溯单元

一个可专利检索的创新点应包含：

```text
R + F + 分配的 S + B + E + 出处/证据级别
```

如果仅存在 `S`，将其归类为特征候选，而非创新点。如果仅存在 `F` 和 `E`，将其归类为发明人问题，因为实现缺失。

## 7. 派生权利要求与证据视图

在 document-model-2026.2 中，接口、约束、场景和追溯属于 R/F/S/B/E 的派生视图，不构成新的核心模型层。每个视图必须有来源、事实状态和适用状态；不能确认时使用 Q，不得用无说明的空数组代替建模。

在案件包含权利要求时，可从最小追溯单元派生：

```text
R/F/S/B/E → CHAIN → PU/PST/CTX → ClaimVersion/ClaimPath
          → ClaimSpan/CF/REL/CT/INT → SupportLink → DOC/EV
```

SysML 的 `satisfy`、`allocate`、`flow`、`refine` 和 `verify` 分别可作为需求满足、功能分配、接口流、语义细化和证据验证的工作流映射。该映射不表示这些关系与专利法概念具有法律等价性。

权利要求特征必须保留对象、属性、关系、动作、条件、顺序、参数和原文位置。从属权利要求按每条合法引用路径展开；不同文献分别命中的特征不得拼接为单文献新颖性覆盖。语义相似度或模型置信度只能形成候选，必须结合原文定位、组合语境和人工复核。
