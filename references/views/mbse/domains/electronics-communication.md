# 电子通信/AI/软件领域 MBSE 建模规则

适用于电子电路、通信系统、天线、信号处理、网络协议、芯片、传感器、控制系统、AI/ML 模型、算法、数据结构、分布式平台及边缘/云架构。

---

## disclosure 模式（交底书建模）

### R/F/S/B/E 提取

- **R（需求）**：信号质量、延迟、带宽、功耗、抗干扰、可靠性、同步、覆盖范围、精度、安全性、热约束
- **F（功能）**：采集、滤波、编码、调制、波束赋形、调度、路由、同步、反馈控制、检测、补偿
- **S（结构）**：电路模块、天线单元、处理器、存储器、射频链路、传感器、总线、协议层、基站、终端、网关、模型、数据帧
- **B（行为）**：信号路径、消息序列、状态转换、时序关系、反馈环路、训练/推理序列、切换或重传过程
- **E（效果）**：可测量的信号、网络、功率、精度、稳定性或控制效果

### 证据边界

- 除非交底书已明确记载，否则将采样率、频段、阈值、协议字段、帧格式、编码规则、模型参数或时序窗口标注为 Q
- 不得从"无线""模块"或"终端"等通用词语推断标准协议、射频频段或通信实体
- 区分数据流、控制流和信号/能量流——三者不可互换

### 接口检查清单

对每个关键接口记录：

| 字段 | 必填内容 |
|------|---------|
| 发送方/接收方 | 模块或实体名称 |
| 载荷 | 信号、帧、数据包、控制指令、测量值、模型输出 |
| 时序 | 同步/异步、触发条件、周期、顺序 |
| 变换 | 滤波、编码、映射、分类、融合、补偿 |
| 证据 | 出处段落/附图及 D/I/N/G/Q/X 标签 |

### 常见失败模式

- 将算法名称当作结构，但缺少数据输入/输出
- 将"提高精度"当作效果，但没有数据集、度量指标或机理
- 将物理信号路径与软件控制路径混为一谈
- 假设交底书未声明的标准合规性或互操作性

## document 模式（专利文本建模）

### 提取要点

- **R**：时延、吞吐量、带宽、功率、信号质量、精度、干扰、同步、覆盖、可靠性、安全性
- **F**：采集、滤波、编码、解码、调制、调度、路由、分类、融合、同步、授权、控制、补偿
- **S**：电路、处理器、存储器、射频链路、天线、传感器、模型、协议层、总线、队列、数据库、终端、服务器
- **B**：消息时序、信号路径、控制回路、状态转换、重试/回退、切换、训练/推理、采样过程
- **E**：已公开的阈值效果、帧格式效果、时序效果、频率效果、功率效果、采样率效果、协议字段效果、模型参数效果

### 接口要求

每个关键接口必须标明发送方、接收方、载荷、方向、时序/触发条件，以及介质/协议（如已公开）。

不得合并以下内容：
- 物理信号路径与软件控制路径
- 请求/响应与失败/超时确认
- 本地处理与云端处理
- 传感器测量与控制指令

### 防护规则

- 不得从泛指的"无线通信"推断协议合规性、频段或帧字段
- 不得凭空编造模型参数、阈值或训练数据
- 缺失的反馈回路应标注为 Q，而非将控制视为闭环

### 权利要求桥接检查

电子通信和软件相关特征进入 `ClaimSpan/CF/REL` 时，应分别标明信号流、数据流、控制流或能量流，以及消息时序、触发条件、协议字段、算法状态和技术效果来源。必须将物理路径与软件控制路径分开回指原文；相似的模块名称或模型名称不能替代接口、输入输出和时序证据。
