# Mode: search — 检索驱动轻量建模

## 适用范围

当需要对复杂技术方案快速构建 MBSE 模型、系统化地自动生成多语检索块时使用。本 mode 吸收自 `检索视图` 的可选 MBSE 模块。

**定位**：可选增强模块。不替代现有关键词+分类方法，而是提供结构化的 F/S/B 最小模型视角来增强检索的覆盖性和可追溯性。需要完整 R/E、权利要求支持或法律评价时，交接至 disclosure/document 及证据包流程。

---

## 前置要求

必须先完成技术方案的基本技术特征分解。MBSE 建模在此基础之上扩展。

---

## 三视图建模（F/S/B）

本 mode 使用轻量三视图，聚焦于驱动检索式生成所需的最小模型。

### F（功能视图）

回答：系统/发明**做什么**？实现哪些功能？产生什么效果？

| 功能ID | 功能名称 | 功能描述 | 输入 | 输出 | 性能指标 |
|--------|---------|---------|------|------|---------|
| F1 | … | … | … | … | … |

**→ 检索块映射**：
- 功能名称/描述 → 六语功能关键词
- 性能指标 → 可选 AND 限定块
- 输入/输出 → 上下游技术领域扩展词

### S（结构视图）

回答：系统/发明**由什么组成**？各组件之间的关系是什么？

| 组件ID | 组件名称 | 类型 | 材料/规格 | 连接/接口 | 所属子系统 |
|--------|---------|------|----------|----------|-----------|
| C1 | … | … | … | … | … |

**→ 检索块映射**：
- 组件名称 → 六语结构关键词
- 材料/规格 → 可选材料块
- 连接/接口 → 邻近运算符组合
- 组件类型 → IPC/CPC 分类提示

### B（行为视图）

回答：系统/发明**如何运作**？步骤流程是什么？各状态如何切换？

| 步骤ID | 步骤名称 | 前置步骤 | 后续步骤 | 执行条件 | 并行/串行 |
|--------|---------|---------|---------|---------|----------|
| S1 | … | — | … | … | … |

**→ 检索块映射**：
- 步骤名称 → 六语方法关键词
- 前置/后续关系 → 邻近运算符或时间顺序限定
- 并行/条件分支 → 可选 AND/OR 组合逻辑

### 映射总表

| 模型要素 | 映射目标 | 示例 |
|---------|---------|------|
| 功能名称 + 描述 | 检索块1「功能/效果」关键词 | F1"能量转换"→ energy conversion, Energieumwandlung, conversion d'énergie |

| 功能+结构交叉 | 可选块4「组合限定」 | F1 AND C1 |

### 六语关键词展开规则

以功能视图为例：

| 语言 | 展开来源 | 关键词候选 |
|------|---------|-----------|
| 中文 | 模型直接提供 | 技术方案中的中文术语 |
| 英文 | 功能描述翻译 + 同义词 | 英文术语及变体 |
| 日文 | 英文→日文 + FI/F-term 验证 | 日文术语 |
| 韩文 | 英文→韩文 + KIPRIS 验证 | 韩文术语 |
| 法文 | 英文→法文 + Espacenet 验证 | 法文术语 |

## 检索要素原子与来源

对于需要进一步连接权利要求或证据包的任务，检索块应附带可选的 `feature_atoms` 和 `query_provenance`：

```text
feature_atoms:
  object / property / relation / action / condition / sequence / parameter
  claim_or_chain_ref
query_provenance:
  input_document_id / input_version_id / source_span
  tool_or_model_id / generated_at / human_decision
```

这些字段只说明检索式从何处产生，不改变 search mode 的轻量定位。

## 检索后证据映射（检索完成后可选）

完成检索并取得可定位的公开文本后，可以输出下列矩阵；检索前不得预填覆盖结论：

| 字段 | 说明 |
|---|---|
| `claim_or_chain_ref` / `feature_atom` | 权利要求片段或模型特征 |
| `document_id` / `publication_number` | 文献标识 |
| `publication_date` / `source_URL` | 日期及定位入口 |
| `document_role` | 线索、对比候选、方法材料或规范资料 |
| `passage_location` | 权利要求、段落、页码、附图或实施例 |
| `matching_basis` | `exact`、`structural`、`semantic`、`partial`、`not_found` |
| `coverage` | `full`、`partial`、`unknown` |
| `candidate_rank` | 检索排序，不是法律判断 |
| `retrieval_hit` | 是否命中 |
| `authoritatively_verified` | 是否完成权威全文核验 |
| `human_decision` | 人工审核结果 |

必须区分 `candidate_rank`、`retrieval_hit` 和 `authoritatively_verified`。命中或排名靠前不等于单一文献完整公开；仅有相似度时仍保持待核验状态。

## 交付物

1. F/S/B 三视图节点表
2. 2~4 个结构化检索块（每块含六语关键词、IPC/CPC 候选、运算符组合建议）
3. 模型追溯矩阵（可选，供后续检索阶段使用）

## 质量门禁

- 每个检索块至少包含中、英两种语言的关键词
- IPC/CPC 候选标注置信度和推断依据
- 不要求证据标签（本 mode 不涉及原文核验）
- 不要求完整追溯链（模型直接映射检索式）；检索后若建立证据映射，必须保留原文定位和人工审核

## 补充规则：检索候选不是法律结论

search mode 只生成检索块、关键词、分类候选和可选的轻量模型关系。语义相似度、关键词覆盖、排序分数或 AI 生成的同义词均只能用于候选发现；未完成权威全文定位和单文件核验时，不能生成 `NB`、`IS` 或“具备/不具备新颖性、创造性”的结论。官方演示、官方手册、预印本和数据集可作为方法线索登记来源性质，但不得被当作申请日前现有技术或中国法规范依据。

检索前的 `pre_search_hypothesis` 只能表示待验证假设，不得写成“未公开”“空白点”或具有新颖性。检索后的 `post_search_observation` 也只能陈述已定位文献和覆盖范围；如需新颖性或创造性评价，应交接给有证据包和单文献规则的后续流程。
